# Режим «Турбо»: дизайн

Дата: 2026-10-05. Путь брейншторма: архитектурный. Все разделы согласованы с владельцем.

## Цель

Третий движок генерации. Агент сам подбирает входные изображения из библиотеки культа и рисует кадр в стиле «42» через ChatGPT-подписку. Пользователь видит только свой запрос и итоговую картинку. Какие изображения выбрал агент, пользователю не показывается.

## Решения

- Движок `turbo`, цена **10 кредитов**. Формат 1:1, качество medium запрашиваются, но решает сервер Codex.
- Агент: AI SDK 7, `ToolLoopAgent`, модель `gpt-6-luna` через ChatGPT-подписку, уровень рассуждения `high`. Генерация ровно одна за запуск.
- Картинка: прямой запрос к эндпоинту Codex Images (`/backend-api/codex/images/edits`, без изображений `/images/generations`), без Codex SDK и без запуска Codex. Тот же вход, что у агента.
- Входных изображений до **10**. Ограничений на повтор одного человека или файла нет.
- Библиотека — файловая система для агента: папки и файлы, только чтение. Исходник `~/Изображения/референсы`.
- Запретов, не влияющих на качество (реальные люди, политика, символика, бренды, NSFW), в инструкции агента нет. Допустимость кадра оценивает генератор.
- Режим Турбо отделён в интерфейсе переключателем «Изображение / Турбо». Галерея общая.
- Если входа Codex нет, Турбо для пользователей не существует.

## Архитектура

`POST /api/generate` принимает `engine: "turbo"`. Обработчик списывает 10 кредитов и вызывает `runTurbo()`. Успех идёт по общему пути: загрузка PNG в S3, запись в `generations`, ответ клиенту. Любой сбой пишет неуспешную запись (`failed`, `cost = 0`), возвращает кредиты и отвечает общей ошибкой. Путь Krea и Ideogram не меняется.

Новый модуль `src/lib/turbo/`:

- `agent.ts` — цикл агента.
- `library.ts` — файловая система над префиксом `library/` бакета, только чтение.
- `tools.ts` — инструменты `listFolder`, `readFile`, `generateImage`.
- `codex-auth.ts` — вход подписки и хранилище токенов.
- `codex-images.ts` — запрос к Codex Images.

Инструкция агента — `src/lib/prompts/turbo.system.ts`. Общие блоки канона (мир, верность запросу, иерархия, плотность, реализм, паспорт стиля, текст по запросу, композиция, вариации) вынимаются в общие константы из `style42.system.ts` и подключаются в обе инструкции. Черновик инструкции: `2026-10-05-turbo-agent-prompt.md`.

В реестре движков Турбо описывается отдельным видом, без полей Gradio-Space. `/api/models` отдаёт Турбо только при рабочем входе Codex.

## Библиотека

- Хранение: тот же бакет, префикс `library/`, ключи `library/<папка>/<файл>`. Агент о хранилище ничего не знает.
- Каждая папка содержит изображения и текстовый файл `описания.txt`. Формат описаний свободный: ни инструкция агента, ни скрипт заливки его не требуют и не проверяют.
- Дерево для инструкции сервер строит на каждый запрос: папки и число изображений, пустые помечены. Кэш в памяти не дольше минуты.
- Заливка: `scripts/sync-library.ts` из локальной папки, идемпотентно (сравнение размера). Запускается для dev и отдельно для prod, на prod только с разрешения владельца. Загрузки через админку нет. Скрипт содержимое описаний не проверяет; перед заливкой на prod владелец сам убеждается, что описания всех папок готовы.

## Инструменты агента

- `listFolder({ path })` — файлы папки с типом (изображение или текст). Нет такой папки: возвращается список существующих.
- `readFile({ path })` — текст возвращается строкой, изображение агент видит как картинку. Нет файла: ошибка с ближайшими именами.
- `generateImage({ prompt, images })` — `images`: от 0 до 10 путей, порядок задаёт номера Image 1…N в промпте. Проверка путей и лимита. Результат: `ok: true`; `ok: false, retryable: true` (ошибка аргументов до генерации, не больше двух повторов); `ok: false, retryable: false` (отказ или сбой). Готовый PNG кладётся в состояние запуска, агент картинку не видит.

Запуск останавливается, когда картинка получена или генерацию окончательно отклонили; иначе по лимиту ходов, который задаёт сервер. На весь запуск ~270 секунд (лимит функции Vercel 300). Агент никогда не спрашивает пользователя.

Запрос к Codex Images: JSON `{ images: [{ image_url: dataURL }], prompt, model: "gpt-image-2", quality: "medium", size: "1024x1024", n: 1 }`, ответ `data[0].b64_json`. Заголовки подставляет `createAuthenticatedFetch`. Модель, качество и размер сервер Codex считает рекомендациями.

## Данные и вход Codex

Миграция (идемпотентная):

- `generations_engine_check` расширяется на `turbo`.
- Колонка `generations.input_images text[]` (пути выбранных изображений, только для отладки).
- Таблица `codex_auth` на одну строку: `tokens jsonb`, `account_id`, `plan_type`, `updated_at`, `last_error`. Токены наружу не отдаются.

Один `OpenAIOAuth` из пакета `openai-oauth-ai-provider` с хранилищем токенов на БД обслуживает и агента (`createOpenAIOAuthProvider({ auth })`), и запрос картинок (`createAuthenticatedFetch(auth)`). Обновление токена идёт под блокировкой Postgres (`pg_advisory_xact_lock` в `withLock`), чтобы параллельные запросы не ломали сессию. Второго входа (например, через Codex CLI) быть не должно: он мешал бы обновлению токена.

Админка: блок «Вход Codex» рядом с «Ключами».

- Статус: вошли или нет, тариф, время обновления.
- «Войти»: показывает код и ссылку и ждёт подтверждения. Пакет держит состояние входа в памяти одной функции, поэтому `POST /api/admin/codex/login` отвечает потоком и живёт до ~5 минут.
- «Проверить»: запрашивает модели аккаунта и убеждается, что `gpt-6-luna` доступна.
- «Выйти»: стирает токены.

## История генераций

Для Турбо пишутся: `engine = 'turbo'`, итоговый промпт агента в `enhanced_prompt`, `input_images`, `llm_model = 'gpt-6-luna'`, токены и время агента в `llm_tokens` и `enhance_ms`, хеш инструкции в `style_version`. Журнал вызовов агента не пишется.

## Ошибки

Каждая ошибка возвращает 10 кредитов и пишет `failed` с кодом `<код>: <текст>` в `error_message`: `codex_auth_required` (нет входа или токен умер), `agent_failed` (сбой LLM), `agent_no_generation` (агент не вызвал `generateImage`), `generation_rejected` (отказ Codex), `agent_timeout`. Деградации (рисовать без агента) нет.

Пользователь всегда видит одно общее сообщение: «Не удалось создать изображение, кредиты возвращены». Состояние входа Codex и причины сбоев видны только в админке. Запрос с `engine: "turbo"` при отсутствии входа получает тот же ответ, что на неизвестный движок.

## Интерфейс

- Сверху по центру переключатель shadcn `Tabs`: «Изображение» и «Турбо», иконки Tabler. Компонент добавляется через CLI (`bunx --bun shadcn@latest add tabs`). Выбранный режим запоминается в браузере. Если Турбо недоступен, переключателя нет, показан один обычный экран.
- «Изображение»: как сейчас, с чипом выбора Krea 2 и Ideogram 4.
- «Турбо»: то же поле и результат без чипа движка. Кнопка с ценой 10, блокируется при балансе меньше 10. Подсказка в поле без технических подробностей.
- Ожидание: один новый общий компонент для всех движков вместо `PopSkeleton`. Анимация в стиле «42» на своих SVG, при `prefers-reduced-motion` статичная. Вид прорабатывается на этапе плана по скиллам дизайна.
- Галерея общая, без пометок режима.

## Тестирование

Автотесты (`bun test`): проверка путей и дерева библиотеки; правила `generateImage`; формат запроса и разбор ответа Codex на подменённом `fetch`; хранилище токенов и блокировка; цикл агента на мок-модели AI SDK со сценариями успеха и каждой ошибки; ветка Турбо в `/api/generate` (списание, возврат, скрытие без входа).

Вручную: первая реальная генерация на аккаунте владельца и проход интерфейса в браузере на dev.

Скрипт `scripts/eval-turbo.ts`: по набору запросов печатает выбранные изображения и итоговый промпт без траты на картинки, для настройки инструкции.

## Риски и проверка

Все проверяются первым шагом реализации на аккаунте владельца, до остального кода.

- Принимает ли эндпоинт Codex Images заголовок `originator` пакета. Если нет, подставить значение, которое он принимает.
- Реальный потолок числа изображений на сервере (документация Hermes: 16, клиент Codex: 5). Если сервер отказывает при 10, лимит уменьшается константой.
- Доступность слага `gpt-6-luna` на аккаунте (проверка «Проверить» в админке). Если нет, взять доступную модель с поддержкой картинок и вызова функций.
- Качество и размер приходят как рекомендация, 2.5 недоступна. Если качество не устроит, `generateImage` переключается на другого провайдера (AI Gateway или API-ключ OpenAI) без изменений остального дизайна.
- Эндпоинт неофициальный, возможны внезапные отказы после обновлений на стороне OpenAI. Лимит подписки общий на весь сайт.
- Время запуска. Пакет входа не запускает Codex, это обычные HTTPS-запросы, а ожидание внешних API Vercel не тарифицирует как активный CPU. Но на Hobby максимум функции 300 секунд (Pro: 800). Агент на `high` делает 3–4 раунда, картинка занимает от ~40 секунд до двух минут. На первом шаге измеряются p50 и p95 всего запуска. Если p95 больше ~200 секунд: сначала снизить рассуждение до `medium`, затем перейти на фоновый запуск (ответ клиенту сразу, результат по опросу статуса) или поднять тариф до Pro.
- Бандл Vercel: пакет входа и его зависимости с разными условиями `exports` могут потребовать записи в `includeFiles` в `vercel.json`. Проверяется `vercel build --prod`.
- Размер изображений библиотеки при просмотре агентом. Если медленно, отдавать уменьшенную копию.

### Результаты проверки на аккаунте владельца (2026-10-05)

- `originator`: принимается значение пакета (`openai-oauth-ai-provider`), `CODEX_ORIGINATOR` не понадобился.
- Потолок входных изображений: прошло 10 из 10; лимит в коде: 10. Самые тяжёлые изображения библиотеки дают тело запроса 5,4 / 18,8 / 26,7 МБ на 1 / 5 / 10 входных.
- `gpt-6-luna`: доступна, агент с ней отработал. Но список моделей Codex фильтруется по `client_version`: пакет по умолчанию шлёт `0.1.0` и получает пустой список. С `0.160.0` (текущий Codex CLI) и выше приходят 10 моделей, включая `gpt-6-luna` (при `0.120.0` — 1, при `0.140.0` — 2). Поэтому «Проверить» передаёт `clientVersion` явно (`CODEX_CLIENT_VERSION`, по умолчанию `0.160.0`, переопределяется переменной окружения).
- Инструкция агента: передаётся обычным полем `instructions`, запасной путь через `providerOptions` не нужен.
- Агент на запросе «пятёрка в очках сидит на троне»: 25 с, 2 шага (параллельные `listFolder` и `readFile`, затем `generateImage`), около 30 тысяч токенов.
- Codex Images: время на 1 / 5 / 10 входных изображений 45 / 105 / 125 с. Размер ответа решает сервер: 1254×1254 (1 и 5 входных) и 1386×1135 (10) вместо запрошенных 1024×1024; качество `low` при одном входном, `medium` при пяти и десяти. Люди и предметы с входных изображений узнаются на всех трёх результатах.

### Время запуска (2026-10-05)

Замеры `bun scripts/eval-turbo.ts --generate`, шесть запросов, сначала `high`, затем `medium`:

- `high`: 169, 224, 72, 74, 82, 85 с (медиана 85, максимум 224).
- `medium`: 176, 100, 87, 88, 119 с и один сбой по сетевому таймауту (медиана 100, максимум 176).

Внутри запуска время делится так: рисование 54–91 с (чаще около 70), фаза агента на `high` — 8–50 с (просмотр изображений агентом иногда добавляет до ~90 с). Общее время сильнее зависит от рисования, чем от уровня рассуждения.

Решение: оставить `high`. На `medium` агент ошибся в выборе героя — на запрос «Мафаня в майке оранджэнг» взял `пятерка/5opka_simple_knee_up_shot.png` вместо `личности/mafanya.png`; на `high` промахов не было ни в одном прогоне, и повторная проверка с `high` снова выбрала `личности/mafanya.png`. Максимум 224 с укладывается в `TURBO_TIMEOUT_MS` (270 с) и в лимит функции Vercel (300 с).

Сбой «флага» — сетевой таймаут (соединение с Codex Images оборвалось примерно на 4,5-й минуте, раньше нашего сигнала 270 с) — не таймаут приложения. Ошибка всё равно превращается в `TurboError` (`generation_rejected`), кредиты возвращаются. Отдельная проба показала: внутренний таймаут сети Bun — 300 с, то есть и на dev, и в проде (рантайм Node, undici с таймаутами 300 с) наш сигнал 270 с срабатывает раньше, и путь ошибки один и тот же.

По итогам прогонов в инструкцию агента добавлено правило: названный в запросе предмет — всегда файл из библиотеки («флаг 42» → `эмблемы/flag_of_42.png`), и пункт 13 самопроверки — пропуск названного считается браком. Проверено повторным прогоном: «флаг 42 над ратушей и салют» берёт флаг из эмблем.

## Вне объёма

Загрузка и правка библиотеки из админки; показ шагов агента пользователю; потоковый протокол генерации; деградация без агента; Codex SDK; GPT Image 2.5 через Gateway (возможное будущее переключение инструмента).

## Документация и процесс

При реализации обновить `AGENTS.md` и `README.md` (движок, цена, вход Codex, библиотека, схема БД). Миграции на prod и заливка библиотеки на prod — только с разрешения владельца. В PR вставить скриншот интерфейса (скилл `before-and-after`).
