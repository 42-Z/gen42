# Спецификация приложения gen42

## Обзор

gen42 — веб-приложение для генерации изображений с использованием модели Krea 2 Turbo через HuggingFace Gradio API. Приложение включает систему кредитов, автоматическое переключение API-ключей и админ-панель.

## Архитектура

### Технологический стек

- **Сервер:** Bun.serve()
- **Фронтенд:** React + Tailwind CSS
- **База данных:** Neon Postgres
- **Объектное хранилище:** Neon Object Storage
- **Аутентификация:** Better Auth (email/password)
- **Деплой:** Vercel

## База данных

### Схема

#### Таблица `users` (Better Auth)

```sql
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email VARCHAR(255) UNIQUE NOT NULL,
  name VARCHAR(255),
  email_verified BOOLEAN DEFAULT FALSE,
  image VARCHAR(255),
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

#### Таблица `sessions` (Better Auth)

```sql
CREATE TABLE sessions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  token VARCHAR(255) UNIQUE NOT NULL,
  expires_at TIMESTAMP NOT NULL,
  ip_address VARCHAR(255),
  user_agent TEXT,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

#### Таблица `accounts` (Better Auth)

```sql
CREATE TABLE accounts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  account_id VARCHAR(255) NOT NULL,
  provider_id VARCHAR(255) NOT NULL,
  access_token VARCHAR(255),
  refresh_token VARCHAR(255),
  expires_at TIMESTAMP,
  token_type VARCHAR(255),
  scope VARCHAR(255),
  id_token TEXT,
  session_state VARCHAR(255),
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

#### Таблица `credits`

```sql
CREATE TABLE credits (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE UNIQUE,
  balance INTEGER DEFAULT 0,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

#### Таблица `api_keys`

```sql
CREATE TABLE api_keys (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(255) NOT NULL,
  key VARCHAR(255) UNIQUE NOT NULL,
  daily_limit INTEGER DEFAULT 100,
  used_today INTEGER DEFAULT 0,
  is_active BOOLEAN DEFAULT TRUE,
  last_used_at TIMESTAMP,
  last_reset_at TIMESTAMP DEFAULT NOW(),
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

#### Таблица `generations`

```sql
CREATE TABLE generations (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  prompt TEXT NOT NULL,
  negative_prompt TEXT,
  model VARCHAR(50) DEFAULT 'Turbo',
  width INTEGER DEFAULT 1024,
  height INTEGER DEFAULT 1024,
  steps INTEGER DEFAULT 8,
  guidance DECIMAL(3,1) DEFAULT 0.0,
  seed INTEGER,
  image_url VARCHAR(255),
  image_key VARCHAR(255),
  status VARCHAR(20) DEFAULT 'pending',
  error_message TEXT,
  duration INTEGER,
  api_key_id UUID REFERENCES api_keys(id),
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

## API Endpoints

### Аутентификация (Better Auth)

- `POST /api/auth/sign-up` — регистрация
- `POST /api/auth/sign-in` — вход
- `POST /api/auth/sign-out` — выход
- `GET /api/auth/session` — текущая сессия

### Генерация изображений

- `POST /api/generate` — генерация изображения
  - Body: `{ prompt, negative_prompt?, model?, width?, height?, steps?, guidance?, seed? }`
  - Response: `{ id, image_url, credits_remaining }`

### Админ-панель

- `GET /api/admin/users` — список пользователей
- `POST /api/admin/credits` — выдача кредитов
  - Body: `{ user_id, amount }`
- `GET /api/admin/keys` — список API-ключей
- `POST /api/admin/keys` — добавление ключа
  - Body: `{ name, key, daily_limit? }`
- `DELETE /api/admin/keys/:id` — удаление ключа
- `GET /api/admin/stats` — статистика

## Генерация изображений

### Алгоритм

1. Проверить аутентификацию пользователя
2. Проверить баланс кредитов (≥ 1)
3. Выбрать доступный API-ключ:
   - Первый активный ключ с `used_today < daily_limit`
   - Если все ключи исчерпаны — ошибка 429
4. Вызвать Gradio API:
   ```
   POST https://krea-krea-2.hf.space/gradio_api/call/generate
   Authorization: Bearer {api_key}
   Content-Type: application/json
   {
     "data": [{
       "prompt": "...",
       "negative_prompt": "...",
       "model": "Turbo",
       "width": 1024,
       "height": 1024,
       "steps": 8,
       "guidance": 0.0,
       "seed": null,
       "randomize": true
     }]
   }
   ```
5. Получить event_id и polling результат:
   ```
   GET https://krea-krea-2.hf.space/gradio_api/call/generate/{event_id}
   ```
6. Скачать изображение по URL из ответа
7. Сохранить в Neon Object Storage
8. Сохранить запись в таблицу `generations`
9. Списать 1 кредит
10. Обновить `used_today` для API-ключа
11. Вернуть presigned URL изображения

### Автоматическое переключение ключей

- При ошибке 429 (Rate Limit) или 503 (Service Unavailable):
  1. Пометить ключ как временно недоступный (`is_active = FALSE`)
  2. Выбрать следующий доступный ключ
  3. Повторить запрос
- При ошибке 401 (Unauthorized):
  1. Пометить ключ как недействительный (`is_active = FALSE`)
  2. Выбрать следующий доступный ключ
  3. Повторить запрос
- Если все ключи исчерпаны — ошибка 429 с сообщением
- Каждый день в 00:00 UTC сбрасывать `used_today` и восстанавливать `is_active` для всех ключей

### Обновление лимитов

- Каждый день в 00:00 UTC сбрасывать `used_today` для всех ключей
- Восстанавливать `is_active = TRUE` для всех ключей
- Опционально: проверять реальные лимиты через API HuggingFace

## Админ-панель

### Функции

1. **Управление пользователями:**
   - Список пользователей с балансом кредитов
   - Выдача кредитов (положительное число)
   - Списание кредитов (отрицательное число)
   - Просмотр истории генераций пользователя

2. **Управление API-ключами:**
   - Список ключей с лимитами
   - Добавление нового ключа
   - Удаление ключа
   - Мониторинг использования
   - Ручной сброс лимитов

3. **Статистика:**
   - Общее количество генераций
   - Генерации по дням
   - Топ пользователей
   - Использование ключей
   - Среднее время генерации

### Доступ

- Только один админ (email захардкожен в конфигурации)
- Проверка `user.email === ADMIN_EMAIL` в middleware

## Безопасность

### Аутентификация

- Better Auth с email/password
- JWT токены для API
- HTTP-only cookies для сессий

### Авторизация

- Проверка сессии на каждом API endpoint
- Проверка прав админа для `/api/admin/*`

### Валидация

- Валидация всех входных данных
- Ограничение длины промпта (макс. 1000 символов)
- Ограничение размера изображения

### Rate Limiting

- 10 генераций в минуту на пользователя
- 100 запросов в минуту на API
- Rate limiting на уровне Bun.serve() middleware

## Деплой

### Vercel

1. Подключить репозиторий к Vercel
2. Настроить переменные окружения:
   - `DATABASE_URL` — Neon Postgres connection string
   - `BETTER_AUTH_SECRET` — секрет для Better Auth (мин. 32 символа)
   - `BETTER_AUTH_URL` — URL приложения (например, `https://gen42.vercel.app`)
   - `ADMIN_EMAIL` — email админа
   - `AWS_ACCESS_KEY_ID` — Neon Object Storage access key
   - `AWS_SECRET_ACCESS_KEY` — Neon Object Storage secret key
   - `AWS_ENDPOINT_URL_S3` — Neon Object Storage endpoint URL
   - `AWS_REGION` — Neon Object Storage region (например, `us-east-2`)
3. Настроить сборку: `bun run build`
4. Настроить команду запуска: `bun run start`

### Миграции

- Better Auth CLI для миграций: `npx @better-auth/cli migrate`
- Drizzle ORM для пользовательских таблиц: `npx drizzle-kit generate && npx drizzle-kit migrate`
