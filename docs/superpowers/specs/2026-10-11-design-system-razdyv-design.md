# Дизайн-система «Раздув» (issue #17)

Дата: 2026-10-11. Статус: идея одобрена владельцем в диалоге («идея интересная»); развилки закрыты решениями по умолчанию (раздел 11) и подтверждаются по живому прототипу. Спецификация заменяет прежние спецификацию и план спецэффектов (движок частиц, фон из объектов): владелец их отверг, они остаются в истории коммитов.

Источник: коллегия из пяти экспертов, трёх критиков и председателя (2026-10-11), полный текст концепции с таблицей решений приложен к диалогу.

## 1. Цель

Один язык для всего интерфейса: любой элемент на любом экране выглядит и отзывается как часть единого материала. Это идея, а не набор украшений: новый элемент выводится из правила, а не рисуется заново. Задача из issue #17: «Улучшить визуал, чтобы все элементы были в едином стиле, с классными анимациями».

Требования владельца (свод):
- градиентный, фиолетово-розовый, плавный вайб; абстракции со «склеенной», «тянущейся» формой;
- никаких отдельных предметов, россыпей и мелких узоров (наклейки, звёзды, кристаллы, шары, линии, капли, полосы с углами, дробный шёлк) ни в фоне, ни в частицах, ни в слайдере, ни в маркерах;
- низкий контраст фона: активная кнопка всегда заметна;
- любое действие (нажатие, регистрация, печать, смена уровня рассуждения) отражается визуально на всех экранах, «обделённых мест» нет;
- слайдер «Рассуждение»: только заголовок и сам слайдер, уровень понятен по эффектам;
- качество не зависит от мощности устройства, нагрузка почти нулевая (принцип Doom: предрасчёт, засыпание без событий);
- **меньше текста, больше визуала** (раздел 3).

## 2. Идея

**«Раздув»: весь интерфейс gen42 — один непрерывный цветной лист (фирменный индиго → фуксия градиент), каждый элемент — окно в этот лист. Любое действие-пустяк вносит в лист импульс, лист раздувает его в отклик больше самого действия, но ограниченный и затухающий, волна доходит до остальных окон с задержкой по расстоянию, потом всё засыпает.**

Откуда: суть 42 — «праздник вокруг пустяка, раздутый до эпоса». Три слова промпта становятся эпосом картинки; интерфейс проживает ту же трансформацию в малом. Замысел пользователя (текст промпта, числа, готовая картинка) лист никогда не красит: он живёт вокруг и под ними, как 42-вайб в картинках.

**Порождающее правило.** Любой элемент = окно на лист + класс массы. Любое событие = импульс (знак: вперёд = успех, ввод, рост; назад = отмена, ошибка, трата; вес по цене действия). Окно сдвигает свой кусок листа и упруго деформируется (перелёт ≤ 4%), остальные окна откликаются позже (≤ 280 мс по расстоянию) и слабее, затем всё неподвижно.

Новый элемент выводится четырьмя вопросами: какой кусок листа и в какой яркостной роли; какого класса массы (лёгкий, средний, тяжёлый); что для него импульс и где «вперёд»; как он засыпает. Нет ответа на вопрос — элемента в системе быть не должно.

### Принципы
1. **Один лист, цвет есть положение.** `hue(p)` по положению на листе; у элемента нет «своего» цвета. Яркость назначает не положение, а роль (две ортогональные оси), поэтому положение не может сломать контраст.
2. **Раздув с причиной.** Нет отклика без события и события без отклика. Усиление > 1, но с потолком; вес импульса зависит от цены действия (Krea 1 < Ideogram 3 < Турбо 10), а не от размера элемента.
3. **Волна.** Задержка 1 мс на 2,5 px, потолок 280 мс, затухание ÷ (1 + d/400 px). Одинаковой одновременной реакции всех элементов нет: источник отвечает первым.
4. **Направление есть смысл.** Вперёд (к фуксии) = продвижение, ввод, успех, рост баланса. Назад (к индиго) = отмена, удаление, ошибка, трата. Ошибка дополнительно значком и текстом, не цветом.
5. **Три массы, один закон пружин.** Лёгкая (каретка, наведение), средняя (кнопки, вкладки, меню, слайдер, полосы), тяжёлая (кадр, занавес, лайтбокс); все в CSS `linear()`. Нарастание ≤ 120 мс, спад 0,6–1,2 с.
6. **Замысел нейтрален.** Лист не красит текст промпта, числа, картинку и подписи (исключения: слово «gen42» и знак «42»).
7. **Запекай и спи.** Тяжёлое считается заранее; в рантайме только `transform`/`opacity` и события; постоянного `requestAnimationFrame` нет.

## 3. Меньше текста, больше визуала

Правило: текст остаётся только там, где его нельзя заменить знаком или положением на листе. Каждый значок и каждое окно без текста имеет `aria-label` на русском, чтобы доступность не страдала.

| Было | Стало |
|---|---|
| «10 кредитов» (подпись у кнопки) | монета (`IconCoins`) и число, слова «кредитов» нет (бейдж цены на кнопке уже такой) |
| Подпись «Промпт» над полем | убирается; поле узнаётся по каретке и кнопке с искрой; `aria-label="Промпт"` |
| «Недавние» | значок (`IconHistory`), `aria-label="Недавние"` |
| Подписи «Быстрее / Дольше…» и текстовое значение у слайдера | убраны; остаётся только заголовок «Рассуждение» (требование владельца); уровень читается по положению на листе и массе ручки |
| Пояснения и подзаголовки под заголовками | не используются |
| Названия стадий ожидания | нет; стадии видны ступенями яркости рамки |
| Состояние баланса | число и монета без слов |
| Админка: заголовки блоков | значок и одно слово; описания убираются; лимиты по-прежнему полосами, а не цифрами |
| Ошибки | значок и одна короткая строка |

Рамки из AGENTS.md сохраняются: русский язык без технических подробностей; иконки Tabler, без эмодзи; без карточек-окошек (структура — типографика, отступы, тонкие линейки); поля с рамкой и скруглением 22 px; без примеров промптов; чип модели в нижней строке поля слева (иконка, имя, цена, галочка у активного); кнопка генерации справа с бейджем цены; сверху `Tabs` «Изображение / Турбо»; все правки UI только через скилл `shadcn`; поведение обновления страницы во время генерации (`localStorage`: `gen42-pending`, `gen42-result`, `gen42-mode`, `gen42-reasoning`) не меняется. Изменятся пункты AGENTS.md про декоративную графику и дизайн-систему (раздел 9).

## 4. Язык системы

### Цвет
Одна функция `hue(p)` и три яркостные роли. Опорные цвета «хребта» (все при относительной яркости L ≈ 0,18; интерполяция в линейном RGB, где L линейна):

| Опора | Цвет | L |
|---|---|---|
| S0 | `#6c5cff` | 0,1806 |
| S1 | `#8a57e8` | 0,1805 |
| S2 | `#a252cd` | 0,1812 |
| S3 | `#b54cad` | 0,1801 |
| S4 | `#c74682` | 0,1813 |
| S5 (только «спектр») | `#ff5ca8` | 0,317 |

- **Тёмная полоса (фон).** `hue(p)` смешан с базой `#0d0b1e` в линейном RGB так, что L ≤ **0,018** в любой точке (на индиго около `#211c55`). Один линейный диагональный градиент 115° без форм; дизеринг ±1/255 против бэндинга.
- **Хребет (всё, что несёт белый текст):** кнопки, активная вкладка, чип модели, бейдж цены. L = 0,18 ± 0,003 при любом `p`: белый текст ≥ 4,5:1, кнопка к фону ≥ 3,3:1.
- **Спектр (чистые заливки без текста):** заливка слайдера, полосы квот, рамка ожидания, занавес, индикатор вкладки. Хребет с продолжением до `#ff5ca8` (L до 0,32).

Текст: `#f2efff` (≈ 13:1 к фону), вторичный `#a79fcb` (≈ 6,2:1), ошибка `#ff6b81` (только текст и значок). Золота, жёлтого, персика в системе нет. Цена честно названа: на кнопках горячий край `#c74682`, а не `#ff5ca8` (белый на `#ff5ca8` даёт 2,9:1).

### Форма
Собственных форм нет, есть геометрия элементов (капсулы, поля 22 px). Единственная выразительная форма — растяжение при движении (`scaleX` до 1,12 по скорости и возврат). Ручка слайдера — капсула, не круг.

### Глубина и свет
Глубина = порядок слоёв и яркостная роль (фон 0,018 → поднятая поверхность до 0,04 → хребет 0,18). Теней, `filter`, `backdrop-filter`, `mix-blend-mode` нет. «Свет» — положение яркой части листа в окне: окно тянет её к курсору, каретке, ручке.

### Движение
Единственный закон: импульс → пружина своей массы → волна по расстоянию → сон. Лёгкая ≈ 0,18 с, ζ = 1,0; средняя ≈ 0,28 с, ζ = 0,75 (перелёт ≈ 3%); тяжёлая ≈ 0,5 с, ζ = 0,9. Нажатие: предвкушение `scale(.97)` ≤ 80 мс, сдвиг листа вперёд, выход на 1,03 и возврат. Анимируются только `transform` и `opacity`; у каждого окна один слой. Единственное движение без события: сверхмедленный дрейф фона (один слой, период 90 с); он стоит при скрытой вкладке и отключён при `prefers-reduced-motion`.

### Типографика
Bricolage Grotesque (заголовки, «Рассуждение», «42»), Inter Tight (остальное). Оси шрифта не анимируются. Числа (баланс, цена, остаток) — `tabular-nums`; при смене старое значение уходит вверх с `opacity`, новое приходит снизу лёгкой пружиной.

### Знаки
Иконки Tabler, штрих, `currentColor`; реакция — сдвиг на 1–2 px в сторону импульса. Бренд-знаков два: слово «gen42», залитое листом (кроссфейд двух копий), и число «42» по одному на бейдже цены, в логотипе и на пике готового кадра. Маркеров заголовков, наклеек, звёзд нет.

### Фон: почему он не состоит из предметов
Фон — тёмная полоса самого листа и больше ничего: ни пятен, ни форм, ни линий. Яркие окна показывают тот же лист (кнопка — место, где фон «зажёгся»), а богатство даёт согласованность во времени: при импульсе цвет едет по листу.

Как строится: три полосы листа запекаются в узкие повторяющиеся текстуры около 1024×32 px (≤ 20 мс при загрузке, иначе на сборке в WebP). Каждое окно — элемент с `overflow: hidden` и внутренним слоем с текстурой листа, смещённым так, чтобы совпасть с фоном в координатах страницы (CSS-переменная, один раз при монтировании и `ResizeObserver`); импульс двигает только `transform` этого слоя. Для `fixed`-элементов (шапка, лайтбокс) используется копия листа в координатах окна просмотра.

## 6. Фирменный момент: «Выдох»
Нажатие «Создать»: кнопка сжимается, лист в ней рывком идёт вперёд, волна проходит по полю, слайдеру и логотипу, из поля вырастает рамка будущей картинки, сквозь неё течёт лист в темпе выбранного рассуждения. Когда кадр готов, лист-занавес сдёргивается и открывает картинку, накопленный сдвиг волной уходит к краям, миниатюры в галерее встают на места; на пике вспыхивает единственное крупное «42» в логотипе. Начало и конец — один материал.

## 7. Чего никогда не делаем
Отвергнутое владельцем: россыпи мелких объектов (наклейки, звёзды, кристаллы, самоцветы, планеты, монеты, кометы, блёстки как предметы, «новогодний» блеск, золото в фоне); круги, шары, орбиты как предметы; длинные линии как объекты; капли, «слайм», мелкие блобы; пересекающиеся прямоугольники и полосы с углами; дробный шёлк, зерно, шум; высококонтрастные розовые волны; мягкие пятна на тёмном фоне; «ещё версии» одного и того же.

Дополнительно: анимация в обход импульса; собственный градиент у элемента; собственная длительность вместо трёх пружин; одинаковая одновременная реакция всех элементов; перелёт > 4%; бесконечные пульсации (кроме дыхания рамки ожидания и дрейфа фона); белый текст на цвете с L > 0,1833; градиентный текст (кроме «gen42» и «42»); окрашивание листом текста, чисел и картинки; ложный прогресс (процент, полоса к 95%); текст и цифры в сцене ожидания; `filter`, `backdrop-filter`, `mix-blend-mode`, анимация теней, `width/height/left/top`, `background-position`, `clip-path`, `@property`-градиенты; смысл только цветом; карточки-окошки; рамки на всём подряд (контур только у полей и дорожки слайдера); движок частиц и объекты, отрывающиеся от курсора; постоянный `requestAnimationFrame`.

## 8. Проверяемые правила

Токены и контраст (`design-tokens.test.ts`, 17 точек `p` ∈ [0, 1], линейный RGB):
1. Хребет: 0,178 ≤ L ≤ 0,1833; белый текст ≥ 4,5:1.
2. Фон: L ≤ 0,018 в каждой точке (запас от предела 0,026 для кнопки 3:1).
3. Хребет к фону ≥ 3,3:1 в любой паре точек.
4. Рамка поля и дорожки: L ≥ 0,154, к фону ≥ 3,3:1.
5. Спектр: 0,178 ≤ L ≤ 0,32; под текстом не используется (проверка DOM: у окон спектра нет текстовых потомков).
6. Текст `#f2efff` ≥ 12:1, `#a79fcb` ≥ 4,5:1, `#ff6b81` ≥ 4,5:1 на любой точке фона.

Движение (`motion.test.ts`, grep по CSS):
7. В `@keyframes` и `transition` эффектов только `transform` и `opacity`; запрещённые свойства отсутствуют во всём `src/**/*.css`.
8. Перелёт ≤ 4%, задержка волны ≤ 280 мс, нарастание ≤ 120 мс, спад 600–1200 мс.
9. Без событий активных анимаций ≤ 1 (дрейф фона); при `prefers-reduced-motion` — 0; `requestAnimationFrame` только внутри обработчика события.
10. Слоёв композитора в покое ≤ 6, во время ожидания ≤ 10; текстуры листа ≤ 400 КБ; запекание ≤ 20 мс; обработка события ≤ 1 мс при замедлении процессора ×4.
11. Ожидание: текстовых узлов (кроме скрытой подписи) и цифр нет.

Покрытие и текст:
12. Тест-страж: у каждого интерактивного элемента (`button`, `a`, `input`, `textarea`, `select`, `[role=tab|slider|menuitem]`) описан импульс (вид и класс массы); «голый» элемент валит `bun test`.
13. Тест текста: в экранах нет строк из списка замененных раздела 3; у значков без текста есть `aria-label`.
14. `prefers-reduced-motion: reduce`: пружины, волна, растяжение, дрейф отключены; смена состояния — мгновенный сдвиг листа с кроссфейдом `opacity` ≤ 150 мс; состояние различимо по положению на листе.

## 9. Реализация

Первым шагом плана — **живой автономный прототип** на реальных токенах и видео около 20 секунд (запись Playwright) для приёмки владельцем до основного кода: идея живёт во времени. Критерии пересмотра: шов окон с фоном ≥ 2 px, слоёв больше предела, перелёт выше 4%.

Модули:
- `src/lib/sheet/palette.ts`: опорные цвета, `hue(p)`, три яркостные роли в линейном RGB (чистый, тестируется);
- `src/lib/sheet/springs.ts`: три пружины в строку `linear()` и расчёт перелёта (чистый);
- `src/lib/sheet/impulses.ts`: шина импульсов: источник, знак, вес, задержки по расстоянию, засыпание; на WAAPI и CSS-переходах, без постоянного цикла;
- `src/lib/sheet/windows.ts`: реестр окон, измерение положения (`ResizeObserver`) и CSS-переменные смещения;
- компоненты: фон `Sheet`, окна в примитивах shadcn (`button`, `input`, `textarea`, `tabs`, `select`, `dropdown-menu`, `slider`, `table`), `ReasoningSlider`, рамка ожидания `GenerationFrame`, хвост каретки `CaretTail`;
- CSS (`src/index.css`): опорные цвета, три яркостные роли, три пружины `linear()` (запасной `ease-out`), `--wave-max: 280ms`, класс окна; существующие `--pop-gradient`, `--color-border` и подобные выводятся из листа или удаляются.

Удаляются: движок частиц и блёстки (в ветке их нет), `graphics-bg.tsx`, `DecoScatter.tsx`, `MeshBackground`, `StickerSpiral`/`StickerRing`, маркеры заголовков, `PopWaitArt` (заменяется рамкой ожидания). `SparkStar` остаётся только если нужна в логотипе (по решению прототипа; золота в системе нет, поэтому логотип пересобирается из листа).

Документы: в `AGENTS.md` обновляются «Стиль UI» (пункты про декоративную графику, ожидание, слайдер, дизайн-систему), `README.md`; тесты старых частиц и фона не создаются.

Вне объёма: звук; выбор пользователем уровня эффектов; изменения бэкенда и схемы БД; WASM и воркеры (стоимость кадра у системы почти нулевая).

## 10. Решения коллегии (кратко)
Основа — механика «Лист и импульс» (слитность из устройства, три массы, волна с задержкой), смысл — «Накал» (пустяк раздувается в эпос, вес по цене, ошибка как потеря хода), дисциплина — «Проявка» (тесты-стражи, асимметрия времени, ступени ожидания только по реальным стадиям). Отвергнуты: температурное поле как фон (те же мягкие пятна), персик и золото, ночная подпись на светлой оси, контуры на всех элементах, зерно и пять канвасов проявки, постоянный цикл «огня» в ожидании, FLIP «кнопка → рамка».

## 11. Решения по умолчанию (подтверждаются по прототипу)
1. Кнопки и вкладки идут от `#6c5cff` до `#c74682`; чистая `#ff5ca8` только в заливках без текста (иначе белый текст не проходит 4,5:1).
2. Блёстки заменены хвостом листа за кареткой; если по видео этого мало, усиливается именно хвост (длина, яркость), а не возвращаются предметы.
3. Сверхмедленный дрейф фона (период 90 с) остаётся; дрейф в главной кнопке отключён в покое (только при наведении, загрузке и ожидании), чтобы в покое была ровно одна анимация.


## Уточнения при планировании (План 1)

- **Геометрия листа.** Градиент 135° на квадратной плитке 1600×1600 px (вместо 115°): при угле угол-в-угол и двух палиндромных волнах на плитку цвет зависит только от (x + y) с периодом в сторону плитки, поэтому плитки стыкуются без шва по обеим осям, а окно выравнивается со страницей смещением `background-position`. Окно — элемент с `overflow: hidden` и **дочерним слоем-элементом** `.sheet-layer` с текстурой листа (не псевдоэлементом: анимация псевдоэлемента через Web Animations в ≈ 9 раз дороже — замер 0,9 мс против 0,1 мс на 14 окон); импульс двигает только `transform` этого слоя (`composite: add`). Геометрия окон кешируется (ResizeObserver, MutationObserver), в обработчике события раскладка не читается.
- **Доля хребта в фоне** 0,075 (вместо ≈ 0,078): фон L ≈ 0,0174, запас от предела 0,018.
- **Индикатор вкладок** — окно **хребта**, а не спектра: под ним стоит белый текст активной вкладки, а спектр под текстом запрещён.
- **Дрейф фона** ±40 px по диагонали с периодом 90 с: бóльшая амплитуда рассинхронизирует фон со статичными окнами.
- **Наведение** — CSS-свойство `translate` слоя окна с лёгкой пружиной (отдельно от `transform`, которым пользуются импульсы).
- **Только 2D-transform.** Статичный `translate3d` делает слой композитным и в покое (замер: 10 слоёв вместо ≤ 6), поэтому везде `translate(x,y)`. Свойство `scale` для вытягивания ручки слайдера и индикатора вкладок не используется: оно складывается с `transform`, поэтому растяжение пишется `scaleX` в том же `transform`.
- **Ожидание**: сервер не сообщает стадии генерации (изменения бэкенда вне объёма), поэтому ступеней яркости две и обе наблюдаемы клиентом: запрос отправлен (0,25) и принят (0,4, для «Турбо» — ответ 202 с идентификатором); дальше рамка дышит. Расширение до реальных серверных стадий — отдельная задача с полем в API.
- **Источник импульса** не получает деформации `scale` от волны (у него своя: сжатие 0,97 → выход 1,03).
- **Бюджет по замерам прототипа (требуется подтверждение владельца).** Обработчик события при замедлении ×4: медиана 1,8–3,3 мс (предел в прототипе 4 мс; в спецификации было ≤ 1 мс — недостижимо: пустая Web-анимация стоит здесь 0,1–1 мс при ×4, а событие создаёт 3–4; без замедления ≈ 0,5–0,7 мс). Волна для дальних окон создаётся по таймеру в момент прихода, поэтому стоимость обработчика не растёт с числом окон. Слои композитора: каркас страницы 6 (7 при записи видео), при ожидании +4.
- **Фон одного семейства оттенков** (индиго → орхидея, S0…S2): малина S3–S4 и фуксия только в окнах и акцентах. Фон со всем путём индиго → малина плыл по диагонали от синего к бордовому и читался «бензиновой плёнкой» (замечание владельца).
- **Нового текста нет нигде** (замечание владельца): ни в переключателе моделей, ни на других экранах. Чип модели — значок и цена, название только в `aria-label`; к существующему тексту приложения ничего не добавляется.
