# Спецэффекты и анимации (issue #17)

Дата: 2026-10-11. Статус: дизайн утверждён владельцем в диалоге, ждёт просмотра спецификации.

## Цель

Единый визуальный язык «живого» интерфейса: фон, декор и реакция на каждое действие пользователя на всех экранах (загрузка, вход, регистрация, главная, админка), в стиле проекта (индиго `#6c5cff`, фуксия `#ff5ca8`, золото `#ffd54a`, хрустальные грани и лучи как в `PopWaitArt`) и с большой детализацией. Отдельной задачей переделывается слайдер «Рассуждение».

## Требования владельца

1. Общая картина: переделать существующий декор (`DecoScatter`, `MeshBackground`) **и** добавить новый фон.
2. Любое действие отражается визуально: нажатия кнопок, регистрация, печать текста, смена уровня рассуждения и т.д., на всех страницах.
3. Печать текста: из курсора ввода летят блестки.
4. Декор не в нескольких местах, а везде: не должно быть «обделённых» мест (экранов, зон, элементов, состояний).
5. Текущие наклейки (30 плоских одноцветных значков) выглядят плохо: заменить детальными объектами.
6. Слайдер рассуждения: оставить только заголовок «Рассуждение» и сам слайдер со спецэффектами, по которым понятен уровень.
7. Качество не зависит от мощности устройства: даже при полном визуальном наполнении нагрузка почти нулевая. Вдохновение: Doom (алгоритмы и предрасчёт, а не грубая сила). Деление на «слабые/мощные» устройства не вводится.
8. `prefers-reduced-motion` соблюдается (доступность): вместо движения короткие статичные вспышки и смена цвета.

## Принципы оптимизации (из Doom)

| Приём Doom | Наш аналог |
|---|---|
| Таблицы вместо вычислений | Таблицы sin/cos, кривых плавности и пружины строятся один раз при старте; в цикле нет `Math.sin`, `Math.random`, вычисления кривых |
| Целочисленная арифметика | Состояние частиц в типизированных массивах (`Float32Array`/`Int16Array`) |
| Предрасчёт карты (BSP) | **Запечённые вспышки и спрайты**: каждый тип эффекта один раз рисуется в атлас; вспышка из сотен частиц стоит один `drawImage` на кадр. Вращение и мерцание частиц задаются переключением заранее повёрнутых кадров (8 кадров), а не трансформом на частицу |
| Рисовать только изменённое | Dirty-rectangles на canvas: очищается и перерисовывается только объединённый прямоугольник активных частиц |
| Фиксированный тик (35 Гц) | Слои фона на CSS тика не требуют. Любые постоянные оживления на canvas (мерцание, фоновые искры) считаются фиксированным тиком ~24 Гц; реакции на действия идут с частотой экрана |
| Нет выделений памяти в цикле | Пул частиц фиксированного размера, ни объектов, ни сборщика мусора в цикле |

Дополнительно:

- **Цикл спит.** Единственный `requestAnimationFrame` запускается шиной событий и останавливается, когда активных частиц нет. Скрытая вкладка останавливает всё (`visibilitychange`).
- **Фон без JS в кадре.** Слои фона двигает только CSS (`transform`, `opacity`) на композиторе. Запрещены в постоянном фоне: `filter`, `mix-blend-mode`, анимация `box-shadow`, `backdrop-filter`. Размытие дальних объектов запекается в атлас.
- **Предохранитель.** Если кадры не укладываются в бюджет, снижается **частота** фонового тика canvas (24 → 12 Гц), а не количество и вид элементов. Решение принимается по измеренному времени кадров, а не по типу устройства.
- **WASM** в первой версии не используется: стоимость кадра определяется отрисовкой (`drawImage` всё равно вызывает JS), расчёт движения на запечённых спрайтах мал. Расчёт частиц изолирован в модуле над одним буфером `Float32Array`, чтобы шаг можно было подменить на WASM без переписывания остального. Порог для пересмотра: шаг расчёта на максимуме эффектов дольше ~1 мс по трассе Chromium. Вторая очередь, если главного потока не хватит: `OffscreenCanvas` в воркере.

## Архитектура

Код движка лежит в `src/lib/fx/`, компоненты в `src/components/`. Модули без зависимостей от React тестируются `bun test`.

### Ядро (`src/lib/fx/`)

- `tables.ts` — таблицы sin/cos, плавности, пружины; детерминированный генератор псевдослучайных чисел (для раскладки и разброса частиц вместо `Math.random` в цикле).
- `atlas.ts` — запекание спрайтов в оффскрин-canvas при загрузке: блёстки (3 цвета × 3 размера × 8 кадров вращения), искры, осколки, вспышки, объекты декора.
- `pool.ts` — пул частиц в типизированных массивах: позиция, скорость, жизнь, кадр спрайта, тип.
- `engine.ts` — цикл: пробуждение по событию, шаг, dirty-rect отрисовка, сон. Бюджет частиц на секунду для лавины событий (быстрая печать).
- `bus.ts` — шина событий `fx.emit(type, x, y, params)`.
- `bindings.ts` — глобальные делегированные слушатели на `document`: `pointerdown`, `input`, `focusin`, `change`, сабмиты форм, и чтение `data-fx` у элемента-источника.
- `caret.ts` — положение каретки: для `textarea` скрытое зеркало с теми же шрифтом, отступами и шириной, замер метки в позиции `selectionStart`; для однострочных `input` ширина текста через `measureText` без раскладки.

### Компоненты

- `Stage.tsx` — единый фон, монтируется один раз в `App` (экран загрузки, вход, главная, админка), `position: fixed`, `contain: strict`. Заменяет разрозненные `MeshBackground` и `DecoScatter` на экранах.
- `FxCanvas.tsx` — canvas событий поверх интерфейса (`pointer-events: none`), подключает движок.
- Эффекты состояний в базовых компонентах shadcn (`src/components/ui/*`).

### Слои `Stage` (снизу вверх)

1. **Mesh-свет.** Запечённая градиентная текстура; «дыхание» — медленный сдвиг `transform` (аналог переливания палитры).
2. **Кристальная пыль в трёх глубинах.** Три бесшовных тайловых слоя (дальний, средний, ближний) из запечённых осколков и искр, дрейф на длину тайла, параллакс за курсором разной глубины.
3. **Наклейки.** Заменяют 30 плоских значков (`graphics-bg.tsx`, `DecoScatter.tsx`). Около 10 детальных объектов (гроздь кристаллов, огранённый самоцвет, шар с орбитальными кольцами, звезда с лучами, комета, призма, монеты, молния-кристалл, цветок из граней, спираль из бусин) в 3 цветовых вариантах, с гранями, градиентом, бликами. Три плана глубины: ближний — крупные, чёткие, яркие (60–90%); средний — лёгкое смягчение; дальний — мелкие, мягкие, запечённое размытие. Раскладка предрассчитана с разбросом (минимальное расстояние между соседями), покрывает весь экран без пустот и кучек. Объекты сгруппированы в три контейнера по глубине: курсор двигает три `transform`, а не десятки.
4. **Свет за курсором.** Один радиальный градиент, сдвигаемый `transform`.
5. **Canvas событий.** Салюты, искры, блестки.

Читаемость: яркие крупные объекты расположены по краям окна и между блоками; внутри колонки с текстом фон спокойнее и мельче. Контраст текста не ниже WCAG AA.

### Реакции фона

- Нажатие: наклейки в радиусе клика получают импульс (отлёт и возврат по запечённой пружине через Web Animations API на композиторе; вызывается только по событию).
- Ввод, ожидание, режим: смена одного атрибута `data-fx` на корне меняет яркость и «темп» слоёв через CSS-переменную без пересоздания анимаций.

## Блестки из курсора ввода

- Печать символа: 3–6 блёсток (золото, фуксия, индиго) из позиции каретки вверх и в стороны с лёгкой гравитацией, жизнь ~0,7 с.
- Стирание (Backspace/Delete): холодная индиго-пыль втягивается в каретку.
- Лавина клавиш ограничена бюджетом пула (плотный шлейф вместо роста нагрузки).
- Область очистки canvas — прямоугольник вокруг активных частиц.
- Работает во всех текстовых полях: промпт, вход, регистрация, поля админки.

## Покрытие («нет обделённых мест»)

- Эффекты встроены в базовые компоненты shadcn (`button`, `input`, `textarea`, `input-group`, `select`, `tabs`, `slider`, `badge`, `card`, `table`, `dropdown-menu`, `label`), чтобы любой экран получал их автоматически.
- У каждого интерактивного элемента определены состояния: наведение, фокус, нажатие, выбор, ошибка, отключено (реакция на попытку нажать), загрузка.
- Декор привязан к элементам: кромки и искры поля промпта, кристалл-маркеры заголовков вместо одинаковой `SparkStar`, уголок-самоцвет и блик плиток галереи, светящиеся кромки карточек и таблиц админки, разделители из бусин с бегущим бликом, пустые состояния, ошибки, баланс.
- **Тест-страж** (`bun test`): сканирует `src/components` и падает, если найден интерактивный элемент (`<button>`, `<a>`, `<input>`, `<textarea>`, `<select>`) вне базовых компонентов или без `data-fx`. Новая страница без эффектов не проходит тесты.

## Слайдер «Рассуждение»

- Видимо: заголовок «Рассуждение» и слайдер. Подписи «Быстрее / Дольше, но продуманнее» и текстовое значение уровня убираются.
- Бегунок-кристалл растёт с уровнем: Среднее — малый самоцвет; Высокое — самоцвет с кольцом; Очень высокое — крупный с двумя кольцами и орбитальными искрами; Максимальное — сияющая звезда с лучами и молнией.
- Дорожка: 4 засечки-кристалла, зажигаются по порядку до выбранной; заливка плотнее и ярче с уровнем.
- Смена значения: вспышка, сила и число искр растут с уровнем; при перетаскивании бегунок оставляет искровой шлейф; пыль вокруг слайдера оживает пропорционально уровню.
- Доступность: `aria-label` и `aria-valuetext` с названием уровня сохраняются (скринридер читает «Высокое» и т.д.).
- Реализация — через компонент `Slider` shadcn (`src/components/ui/slider.tsx`), без самописного аналога.

## Бюджет и приёмка

Измеряется скриптом Playwright (Chromium) с трассой производительности (`scripts/fx-perf.ts`):

- В простое: 0% загрузки главного потока от эффектов, ни одного кадра отрисовки на canvas.
- На максимуме эффектов (салют + быстрая печать + параллакс): не более ~4 мс скриптов на кадр и ни одной сборки мусора в цикле.
- Число композитных слоёв фона 6–8.
- `bun test` (в том числе тест-страж покрытия), `bun run lint`, `bun run typecheck`, `bun run build` проходят.
- Визуальная проверка в браузере (`agent-browser`/Playwright) на экранах: вход, регистрация, главная (оба режима), ожидание, результат, галерея, админка; скриншоты до/после в PR.

## Порядок работ

1. Ядро: таблицы, атлас, пул, движок, шина, привязки, `FxCanvas`, `Stage` (без нового декора).
2. База: эффекты состояний в компонентах shadcn и тест-страж покрытия.
3. Блестки из каретки (`caret.ts` и реакции полей).
4. Слайдер «Рассуждение».
5. Новые объекты декора и слои `Stage`; замена старых наклеек.
6. Реакции по экранам из инвентаря.
7. Замеры, подгонка бюджета, обновление `AGENTS.md` и `README.md` (описание набора спецэффектов, правил `data-fx` и теста-стража).

## Вне объёма

WASM и `OffscreenCanvas` (см. раздел «Принципы оптимизации»); звуковые эффекты; выбор пользователем уровня эффектов; изменения бэкенда и схемы БД.

## Риски

- Яркий декор снижает читаемость текста — смягчено зонами покоя и проверкой контраста.
- Замер каретки в `textarea` требует чтения раскладки — один замер на нажатие, проверяется трассой.
- Запечённые атласы увеличивают время старта — запекание делается один раз и распределяется по кадрам (`requestIdleCallback`), проверяется замером.
