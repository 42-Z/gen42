# gen42

Генерация изображений по текстовому описанию. Пользователь пишет промпт — приложение тратит кредиты (1 за Krea 2, 3 за Ideogram 4, 10 за режим «Турбо») и возвращает готовый кадр, сохраняя его в личной галерее.

**https://gen42.vercel.app**

## Как это работает

- Монолит на Bun: один сервер отдаёт и API, и собранный фронтенд
- React 19 + Tailwind v4, UI-компоненты shadcn/ui, иконки Tabler
- Аутентификация Better Auth (email/password), сессии в Postgres
- База — PostgreSQL (любая из `DATABASE_URL`), картинки — S3-совместимое хранилище (Bun S3)
- Каждый запрос пользователя проходит через LLM-обогащение: короткий промпт превращается в плотное описание сцены в стиле «42» и только потом уходит в генератор изображений. Для пользователя это невидимо
- Главный принцип: по простому промпту получается «42-безумие» — радужные шубы, мопсы, роскошь, RGB, число 42, — но задумка пользователя (герой, действие, место, цвета, текст) никогда не теряется, а лишь пропитывается 42-вайбом. Эталон стиля — `docs/42_images/`
- Изображения генерируют два движка на выбор: Krea 2 и Ideogram 4 (оба — Gradio Space на HuggingFace, пул API-ключей): у бесплатного ZeroGPU суточные лимиты секунд GPU и прогонов (8 на токен), исчерпанные ключи пропускаются ещё до вызова и возвращаются сами после сброса; если LLM-ключи кончились, промпт собирается шаблоном — генерация не падает
- Режим «Турбо»: умный агент сам придумывает идею кадра и подбирает входные изображения из библиотеки культа (если запрос про песню, сначала читает её текст оттуда), а основу Пятёрки выбирает из его снимков по выпавшей идее: сравнивает разные кандидаты взглядом и объясняет себе выбор одной фразой, откинув нарядный дефолт и «удобную» нейтральную базу. Идея, носитель (фото, 3D, комикс, аниме) и десятки решений кадра разыгрываются инструментом `random` из вариантов, которые агент выписывает сам, поэтому один и тот же запрос даёт разные кадры; реплики и надписи по сцене агент тоже придумывает сам. Человек, названный в запросе хоть раз — даже через его фанатов, — появляется в кадре своим портретом из библиотеки, а не безликой толпой. Глубину рассуждения агента выбирает пользователь ползунком от среднего до максимального уровня: чем выше, тем дольше ждать (запуск на максимальном уровне занял около 10 минут, в худшем случае до ~14). Режим появляется у пользователей, только когда админ выполнил вход Codex в админке. Запуск идёт воркфлоу Vercel Workflow, страница ждёт результат опросом
- Кредиты: у каждого пользователя баланс, стоимость зависит от движка (Krea 2 — 1 кредит, Ideogram 4 — 3); при регистрации сразу даётся 42 кредита, и столько же начисляется ежедневно около полуночи по МСК (крон Vercel); админ может менять баланс
- История: каждая попытка генерации пишется в `generations` с исходным промптом пользователя; неуспешные — со статусом `failed` и причиной в `error_message` (кредиты за них возвращаются), в галерею и статистику попадают только успешные
- Генерация переживает обновление страницы: строка истории появляется в статусе `running` ещё до списания кредитов, страница находит идущую генерацию и дожидается результата опросом, а последняя показанная картинка остаётся на экране после обновления. Если процесс погиб вместе с сервером, генерация помечается прерванной (`interrupted`), кредиты возвращаются
- Админка: статистика, управление кредитами и ключами обоих провайдеров

## Запуск

```bash
bun install
cp .env.example .env   # заполнить переменные
bun run db:migrate     # создать таблицы
bun dev                # http://localhost:3000
bun test               # тесты
```

Первый пользователь с email из `ADMIN_EMAIL` становится админом при регистрации.

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Строка подключения PostgreSQL |
| `BETTER_AUTH_SECRET` | Секрет Better Auth, минимум 32 символа |
| `BETTER_AUTH_URL` | Базовый URL приложения |
| `ADMIN_EMAIL` | Email, который получает права админа |
| `CRON_SECRET` | Секрет ежедневного крона кредитов: Vercel шлёт его как `Bearer` в `/api/cron/daily-credits`; локально нужен только для проверки роута |
| `S3_*` | Доступ к хранилищу картинок (ключ, секрет, endpoint, регион, бакет) |
| `POOLSIDE_BASE_URL` | Необязательно. База OpenAI-совместимого API для обогащения промпта (по умолчанию Poolside) |
| `POOLSIDE_MODEL` | Необязательно. Модель обогащения (по умолчанию `poolside/laguna-xs-2.1`) |
| `INCEPTION_BASE_URL` | Необязательно. База OpenAI-совместимого API Inception Labs (по умолчанию `https://api.inceptionlabs.ai/v1`) |
| `INCEPTION_MODEL` | Необязательно. Модель обогащения Inception (по умолчанию `mercury-2.5`) |
| `CODEX_ORIGINATOR` | Необязательно. Заголовок `originator` для запросов подписки (по умолчанию значение пакета; если Codex его не принимает, `codex_cli_rs`) |
| `CODEX_CLIENT_VERSION` | Необязательно. Версия Codex CLI для запроса списка моделей (по умолчанию `0.160.0`) |

### Ключи

Ключи всех провайдеров хранятся в таблице `api_keys` (`provider`: `huggingface` — генерация картинок, `poolside` и `inception` — обогащение промпта) и управляются через админ-панель: добавление с выбором провайдера, проверка с включением, удаление. У HF-ключей видны остатки обеих квот ZeroGPU (секунды и прогоны), а «Проверить и включить» включает ключ только если есть и секунды, и прогоны. LLM-провайдеры образуют единый пул: ключ с бо́льшим остатком используется первым, ключи без измеренного остатка — последними. В переменных окружения ключи не хранятся, API отдаёт их в маскированном виде.

### Стиль «42»

Стиль задан системным промптом `src/lib/prompts/style42.system.ts` и дублируется серверными инвариантами в `src/lib/prompts/style-hints.ts` (чтобы модель не путала медиум, не теряла субъекта и не выдумывала надписи). Замысел пользователя — герой, место, действие, цвета и текст — важнее канона: якоря 42 только наполняют кадр вокруг него. Для итераций есть `bun scripts/eval-style42.ts` (текстовый прогон промптов) и `bun scripts/eval-images.ts` (визуальный прогон через Krea 2).

## Деплой на Vercel

Сборка для Vercel собственная, в формате Build Output API: `vercel.json` задаёт `buildCommand: bun run build:vercel`, а `scripts/build-vercel.ts` собирает сервер одним файлом (`Bun.build` с плагином Workflow), фронтенд и функции Workflow (обработчик очереди `flow` и вебхук). Пресет `framework: bun` не подходит: его сборщик не применяет плагин Workflow, и `start()` не получает идентификатор воркфлоу. Подробности и результаты проверок: `docs/superpowers/specs/2026-10-08-turbo-workflow-design.md`.

Нужен Bun не ниже 1.4.2: в 1.4.0 плагин получает испорченный путь, если в пути проекта есть не-ASCII символы.

## Структура

```
src/
  server.ts        # entrypoint: Bun.serve, API-роуты + раздача dist/
  frontend.tsx     # корень React-приложения
  api/             # auth, generate, admin
  lib/             # db, auth, credits, keys, models, hf, llm, enhance, storage, rate-limit, migrate
  lib/turbo/       # режим «Турбо»: библиотека, вход Codex, картинки, определение агента, приём запуска
  lib/prompts/     # системный промпт 42-стиля и инструкция агента Турбо, общий канон, якоря
  components/      # экраны (Auth, Generate, Admin) и ui/
workflows/         # воркфлоу Турбо (Vercel Workflow): оркестрация и шаги
build.ts           # сборка фронтенда в dist/
workflow-transform.ts  # плагин Bun: преобразование кода для Workflow (dev и сборка для Vercel)
scripts/           # смоук LLM и Codex, eval-прогоны стиля и Турбо, заливка библиотеки, утилиты
```
