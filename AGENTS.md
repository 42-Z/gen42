# AGENTS.md

Инструкции для агентов, работающих с этим репозиторием.

## Главный принцип продукта

По простому промпту приложение делает «42-безумие», но **никогда не упускает задумку, которую написал пользователь**: героя, действие, место, цвета и текст. Задумка остаётся центром кадра и лишь пропитывается 42-вайбом — пёстрыми образами, свитой, роскошью, числом 42. Обилие 42 без просьбы — норма; ошибка — только подмена или потеря замысла. Эталон стиля — картинки сообщества в `docs/42_images/`: сверяйся с ними, когда меняешь промпт улучшателя.

## Стек и конвенции

Везде используем Bun вместо Node.js:

- `bun <file>` вместо `node`/`ts-node`
- `bun test` вместо jest/vitest
- `bun install`, `bun run <script>`, `bunx <package>`
- Bun сам загружает `.env` — dotenv не нужен
- Нужен Bun не ниже 1.4.2. Корневой `bunfig.toml` подключает плагин Workflow (`preload`), и в Bun 1.4.0 его `onLoad` получает испорченный путь, если в пути проекта есть не-ASCII символы (у владельца это «Рабочий стол»): `bun файл.ts` падает с ENOENT. `bun run <script>` берёт Bun из `node_modules/.bin` (1.4.2) и работает; для прямого запуска вне скриптов использовать `node_modules/.bin/bun файл.ts` или обновить глобальный Bun
- В коде, достижимом из шагов Workflow (`workflows/**`, `src/lib/**`), не писать `import … from "bun"`: сборщик Workflow бандлит шаги esbuild и не разрешает этот импорт в финальном бандле. Использовать глобальный `Bun.*` (например, `new Bun.S3Client(…)` в `src/lib/storage.ts`)

Разовые скрипты на Python запускать через `uv run`, в том числе inline:

```bash
uv run - <<'EOF'
print("hello")
EOF
```

`--no-project` добавлять только когда в директории есть `pyproject.toml` и проект не нужен. Никаких `python3 -c` напрямую.

API:

- `Bun.serve()` с `routes` — никаких express/fastify
- `postgres` (postgres.js) для Postgres через `src/lib/db.ts` — не смешивать с `Bun.sql`
- `Bun.s3` для хранилища — не тянуть aws-sdk
- `Bun.file` вместо `node:fs` readFile/writeFile

Фронтенд:

- HTML imports: `index.html` в корне импортирует `./src/frontend.tsx` и `./src/index.css`, Bun bundler собирает сам. Vite не использовать
- Сервер отдаёт статику из `dist/` (см. `src/server.ts`)

## Архитектура

- `src/server.ts` — основной entrypoint: API-роуты (`/api/auth/*`, `/api/generate`, `/api/generations`, `/api/generations/active`, `/api/generations/:id`, `/api/me`, `/api/models`, `/api/admin/*`, `/api/cron/*`) + раздача `dist/`. Обработчик очереди Workflow (`flow`) локально монтируется в этот же сервер (`/.well-known/workflow/v1/flow`, только вне продакшена); на Vercel это отдельная закрытая функция `.well-known/workflow/v1/flow.func` из `bun run build:vercel` (триггер очереди пишет `workflow build`)
- `src/lib/models.ts` — реестр движков генерации `IMAGE_MODELS` (krea / ideogram): адрес Space, стоимость в кредитах, таймаут; Турбо описан отдельно (`TURBO_MODEL`, 10 кредитов, без Space); `publicImageModels({ turbo })` отдаёт клиенту только `id/label/cost` и добавляет Турбо только при рабочем входе Codex
- `src/lib/llm.ts` — единый клиент LLM-провайдеров: реестр `LLM_PROVIDERS` и generic `callLlm({ provider, … })` на AI SDK v7 (`ai` + `@ai-sdk/openai-compatible`)
- `src/api/` — обработчики роутов; `src/lib/` — доменная логика (credits, keys, models, hf, llm, enhance, storage, rate-limit); `src/lib/prompts/` — промпт-инженерия стиля «42»
- Ключи всех провайдеров живут только в таблице `api_keys` (`provider`: `huggingface` | `poolside` | `inception`) и управляются через админку (`/api/admin/keys`: добавление, проверка, удаление; `?provider=` выбирает список). В env и файлах они не хранятся, API отдаёт их маскированными
- Баланс пользователя: генерация списывает стоимость движка из `IMAGE_MODELS` (Krea 2 — 1, Ideogram 4 — 3, Турбо — 10) — `src/lib/credits.ts` (`deductCredits`/`refundCredits`). Новому пользователю при регистрации даётся 42 кредита (`grantSignupCredits`, hook `databaseHooks.user.create.after` в `src/lib/auth.ts`; константа `SIGNUP_BONUS_CREDITS` = `DAILY_GRANT_CREDITS`)
- Ежедневная выдача: крон Vercel (`vercel.json` → `crons`, `0 21 * * *` = 00:00 МСК) бьёт в `GET /api/cron/daily-credits`, секрет — `Bearer CRON_SECRET` (переменная `CRON_SECRET` в Vercel; без неё роут отвечает 401). Начисление — `grantDailyCredits()` в `src/lib/credits.ts`: один атомарный SQL, `+42` (`DAILY_GRANT_CREDITS`) каждому, у кого строки `credits` нет или `last_grant_date < сегодня (МСК)`; идемпотентно (повторный вызов за день — 0), гонка двух одновременных вызовов закрыта `IS DISTINCT FROM` в `DO UPDATE`. Hobby-план запускает крон «внутри часа» — выдача приходит между 00:00 и 01:00 МСК, а не ровно в полночь; Vercel не ретраит упавший крон — пропущенный день значит потерянную выдачу для всех (догонок нет, защита от дублей есть). Неактивные пользователи копят 42/день без ограничений — осознанно
- Первый пользователь с email из `ADMIN_EMAIL` — админ

## Хранилище (S3)

- `src/lib/storage.ts` использует `Bun.s3` (`S3Client`). Env: `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_ENDPOINT`, `S3_BUCKET`, `S3_REGION`. Bun по умолчанию ходит path-style, что и требуется S3-совместимым провайдерам
- Прод — единый Neon-проект `gen42-storage` (`rapid-water-10723622`, `us-east-2`, ветка `main`): и Postgres (`neondb`), и **Neon Object Storage** (бакет `images`, private, чтение через presigned URL). Старый проект БД `gen42` (`steep-block-68050198`, `us-east-1`) не используется — данные переехали 2026-09-15 (pg_dump/restore, сверены md5 всех 7 таблиц)
- Локальная разработка — ветка `dev` в том же проекте (копия `main`, свой изолированный бакет). `bun dev` подхватывает `.env.development` (dev-DATABASE_URL + dev-S3), продовый `.env` не трогает; `NODE_ENV=production` берёт прод
- S3-креды Neon **branch-scoped** и выдаются так (запускать из `/tmp`: `--file` не принимает абсолютный путь):

  ```bash
  neon env pull --file storage.env --project-id rapid-water-10723622 --branch main -s object-storage
  ```

  Затем разложить `AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY/AWS_ENDPOINT_URL_S3/AWS_REGION` → `S3_*`. `env pull` выдаёт новую пару ключей; после ротации перезалить их в Vercel и GitHub. Смена кредов вступает в силу только после редеплоя

## Генерация (HuggingFace)

- `src/lib/hf.ts` — общий Gradio-клиент `callSpace()`: `POST {space}/gradio_api/call/v2/{api}` (payload именованными полями, без старого `data: [ {…} ]`, иначе `event: error`), затем опрос `…/call/v2/{api}/{event_id}` с фолбэком на `…/call/{api}/{event_id}` при 404. Ответ: `data[0].url` (картинка), `data[1]` — seed. Движки задаются реестром `IMAGE_MODELS` (`src/lib/models.ts`), `generateImage({ engine, … })` диспатчит по нему
  - **Krea 2** — `krea-krea-2.hf.space`, поля `prompt/negative_prompt/model/steps/guidance/width/height/seed/randomize` (model `Turbo`/`Raw`, guidance 0, steps 8)
  - **Ideogram 4** — `ideogram-ai-ideogram4.hf.space`, поля `prompt/mode/upsampler/width/height/seed/randomize_seed`. Режим фиксирован `Default · 20 steps`, апсемплер `Ideogram (remote)` (Space сам фолбэчит на локальный Qwen); negative prompt и `model` Ideogram не принимает. Таймаут опроса больше (180с из-за 20 шагов)
- Ключ HF передаётся только в заголовке `Authorization`; актуальную схему эндпоинтов смотреть в `GET /gradio_api/info`
- У бесплатного ZeroGPU два суточных лимита на токен: секунды GPU и **прогоны** (`runs`, 8/сутки). `getZeroGPUQuota()` сохраняет оба (`hf_current`/`hf_resets_at` и `hf_runs_remaining`/`hf_runs_limit`/`hf_runs_resets_at`), админка показывает две полосы — «Секунды» и «Прогоны»
- `getAvailableKey('huggingface')` пропускает ключи без доступных секунд (`< 60`) или прогонов (`0`); после сброса (`resets_at` в прошлом) устаревшие счётчики не блокируют ключ. Ротация выбирает следующий ключ **до** вызова, а не после отказа
- Исчерпание ZeroGPU приходит как `event: error` при HTTP 200 (сообщение Space может ссылаться на секунды, хотя причина — прогоны). Такой ответ распознаётся как `KeyExhaustedError` по словам `ZeroGPU`/`quota`: квота ключа тут же обновляется с `last_error`, ключ не выключается — дальше его отфильтрует остаток по `runs`. Прочие `event: error` — обычная ошибка с текстом из payload

## Обогащение промпта (LLM, стиль «42»)

- Каждая генерация сначала проходит через `src/lib/enhance.ts`: пользовательский запрос превращается в плотный англоязычный промпт в стиле «42» и только потом уходит в выбранный движок (Krea 2 или Ideogram 4). Для пользователя это невидимо, контракт `POST /api/generate` не менялся (добавилось поле `engine`)
- LLM — два OpenAI-совместимых провайдера в реестре `src/lib/llm.ts` (`LLM_PROVIDERS`), вызов — generic `callLlm({ provider, … })`:
  - `poolside` — `POOLSIDE_BASE_URL` (по умолчанию `https://inference.poolside.ai/v1`), `POOLSIDE_MODEL` (по умолчанию `poolside/laguna-xs-2.1`), thinking выключен через `providerOptions.poolside.chat_template_kwargs.enable_thinking`
  - `inception` (Inception Labs) — `INCEPTION_BASE_URL` (по умолчанию `https://api.inceptionlabs.ai/v1`), `INCEPTION_MODEL` (по умолчанию `mercury-2.5`); `reasoning_effort: low` передаётся штатной опцией `providerOptions.inception.reasoningEffort`; rate-limit заголовков нет → `rl_*` = `NULL`; 401/402/403/429 = «ключ не работает» (402 у Inception — биллинг/квота)
- Ключи LLM живут в той же таблице `api_keys` с `provider = 'poolside'` (префикс `sky_`) или `provider = 'inception'` (формат ключа не фиксирован — достаточно непустой строки); у HF-ключей `provider = 'huggingface'`. Ротация: `getAvailableLlmKey()` берёт из единого пула обоих провайдеров по заголовку `x-ratelimit-remaining-requests` и по 429/401/402/403; ключи без замеров (`NULL`, как у Inception) сортируются последними. При исчерпании всех ключей промпт собирается шаблоном `src/lib/style42-fallback.ts` — генерация не падает
- Системный промпт стиля — `src/lib/prompts/style42.system.ts` (TS-модуль, а не `.md`: текстовый импорт Bun не понимает NFT-трассировщик Vercel). SHA-хеш содержимого пишется в `generations.style_version` — по нему сравниваются итерации
- Серверные инварианты из промпта продублированы в коде (`src/lib/prompts/style-hints.ts`): явный стиль пользователя («фотореализм», «аниме», «детский рисунок» и т.п.) вытесняет якорь медиума, финальная формула с медиумом гарантируется постобработкой, экшен-детали и названный герой (мопс, кот, опоссум…; политик → Босс) проверяются по мини-глоссарию (потеряли — повтор с `MISSING DETAILS`)
- Замысел важнее канона: обилие 42 и свиты без просьбы — норма, ошибка только в подмене замысла. Место и цвета/свет из запроса (`detectUserSetting`/`detectUserPalette`) убирают якоря `location`/`lighting` из сообщения (строка `USER-DEFINED`). Якоря идут в начале сообщения, запрос пользователя — последним с напоминанием открыть промпт его героем. Если подлежащее первого предложения — свита из канона, о которой не просили (`hijackedOpening`), — повтор. Ответ LLM с мелкими огрехами (потерянная деталь, свита в начале) возвращается как лучший кандидат, шаблонный fallback — только когда LLM не ответила вовсе
- Якорь медиума всегда реалистичный (фото, 3D, кадр из фильма, обложка рэп-альбома); стилизации — только по запросу пользователя
- Бриф в конце сообщения (`buildBrief`): маленькая LLM теряет правила из длинного системного промпта, поэтому главное для конкретного запроса повторяется последними строками — `MAKE THE IDEA OBVIOUS` (действие и предметы запроса крупно и дважды), `GROUP` (3–5 участников группы описаны по отдельности, двух одинаковых образов нет), `LISTENING` (наушники на каждом, обложка альбома) и `42 VIBE` (выжимка приёмов из `docs/42_images/`: герой сам носит 42-образ, радужные лоскутные шубы, RGB, фантазийная свита, 42 на предметах, радужно-золотая палитра)
- Раздел «Гардероб, пестрота и 42-вайб» системного промпта описывает приёмы эталонов: замысел читается с первого взгляда, герой крупно; каталог образов; подсветка и эффекты; как 42 живёт на предметах; фантазийная свита; музыка. Флаги культа — горизонтальный двухцвет (синий верх, красный низ, белая 42 в золотом лавровом венке): «blue-and-red flag» генератор рисует как государственный
- Названный герой-животное (мопс, кот, свинья…) обязан быть в первом предложении, а действия «слушают» и «ест» проверяются по наушникам и еде (`missingDetails`); название альбома или трека («альбом Magnum») — точный текст на обложке (`extractNamedTexts`)
- Лексикон сообщества в системном промпте: Пятёрка/5opka, Magnum/Opus, взвод/рота/батальон (номер отряда, а не количество), братухи, SLAY, агитация — чтобы маленькая LLM не превращала «3 взвод» в трёх волков
- Политика текста: слова и лозунги появляются в кадре только по запросу. Текстовый запрос — кавычки «», “”, "" (`extractQuotedTexts`), слова «надпись/плакат/агитация/афиша/обложка» (`requestsText`) и лозунги капсом (`extractCapsPhrases`, строка `TEXT CANDIDATES`); «под названием X» (`extractNamedTexts`) — точный текст X. Без текстового запроса слоган-якорь не передаётся, а найденные в ответе цитаты маскируются постобработкой (`maskUnrequestedTexts`); точный текст пользователя переносится дословно и проверяется (`EXACT TEXT`). Кириллические имена из запроса, оставленные LLM без кавычек, берутся в кавычки (`quoteUserCyrillic`), а перед генератором «…» заменяются на "…" (`toGeneratorQuotes`) — ёлочки Krea рисует буквально. В блоке «Примеры» промпта цитируется только текст из INPUT примеров — это покрыто тестом-стражем
- Плотность и экшен: палитра по умолчанию — `hyper-saturated rainbow-and-gold`, промпт 200–300 слов (контракт обрезает на 2000 символах); промпт требует три слоя кадра, минимумы по существам/технике/роскоши/архитектуре (восьмой якорь `props` — абсурдный реквизит), ≥3 сюрприза и явное действие в первом предложении с усилением в 2–3 местах; реализм материалов и света обязателен, `toy-like`/`flat` запрещены
- В `generations` пишутся `enhanced_prompt`, `llm_key_id`, `llm_model`, `llm_tokens`, `enhance_ms`, `style_version`
- Жизненный цикл записи генерации (`src/lib/generations.ts`): строка появляется в статусе `running` ещё до списания кредитов; `POST /api/generate` принимает опциональный `id` от клиента (иначе страница не нашла бы процесс после обновления). `cost` строки — списанные кредиты: списание (`chargeGeneration`) идёт одной транзакцией с отметкой на строке, а сбойное закрытие (`failGeneration`) и ленивое закрытие зависших — одной транзакцией с возвратом кредитов. Закрытие идёт по условию `status = 'running'`, поэтому возврат происходит ровно один раз — ни двойного, ни потерянного
- Неуспешные генерации тоже пишутся в `generations`: `status = 'failed'`, `cost = 0` (кредиты возвращены), исходный `prompt`, всё, что успело прийти от LLM, и причина в `error_message` в формате `<код>: <текст ошибки>` (`insufficient_credits`, `all_keys_exhausted`, `key_exhausted (<status>)`, `queue_timeout`, `error`, коды Турбо, `interrupted`) — `src/lib/generation-error.ts`. Сбой этой записи логируется и не меняет ответ пользователю. Галерея `/api/generations` и `/api/admin/stats` считают только `status = 'completed'`. FK `api_key_id` — `ON DELETE SET NULL`, удаление HF-ключа не блокируется историей
- Обновление страницы не теряет процесс: `GET /api/generations/:id` отдаёт статус записи (с пресайннутой картинкой для завершённой), `GET /api/generations/active` — идущую генерацию пользователя (для вкладок без своего id); клиент опрашивает их каждые 2,5 с. Зависшие `running` старше `GENERATION_STALE_MS` (16 минут: воркфлоу Турбо идёт до ~13–14 минут при агенте на 500 с, остальные движки укладываются в maxDuration; срок должен быть больше худшего прогона, это проверяет `turbo-budgets.test.ts`) лениво помечаются `interrupted` с возвратом кредитов
- Итерации стиля: `bun scripts/eval-style42.ts [подстроки…]` (21 промпт → JSONL в `docs/evals/`), визуальный прогон — `bun scripts/eval-images.ts [подстроки…]` (картинки в `docs/evals/images/`, вне git)
- Админка: блок «Ключи LLM» — селект провайдера (Poolside / Inception), добавление (`sky_` для Poolside, непустая строка для Inception), колонка «Провайдер», остаток запросов, токены, кнопка «Проверить и включить» (тестовый вызов) и удаление

## Режим «Турбо»

- Третий движок `turbo`, 10 кредитов. Запуск идёт воркфлоу Vercel Workflow (`workflows/turbo/`): `POST /api/generate` создаёт строку `running`, списывает кредиты, стартует воркфлоу через `start()` и сразу отвечает `202 { id, engine, cost }`; страница ждёт результат опросом `/api/generations/:id` (таймаут клиента 15 минут). Агент (`WorkflowAgent` из `@ai-sdk/workflow`, модель `gpt-6-luna` через подписку ChatGPT, рассуждение выбирает пользователь ползунком, по умолчанию `high`) сам выбирает входные изображения из библиотеки и принимает итог вызовом `generateImage` (инструмент только проверяет аргументы); картинку рисует отдельный шаг `draw` прямым запросом к приватному Codex Images (`/backend-api/codex/images/edits`, до 10 входных, формат и качество запрашиваются 1:1 и medium, но решает сервер). Пользователь видит только запрос и итог
- Код: `workflows/turbo/index.ts` (воркфлоу: `prepare`, цикл агента, `draw`, `complete`, при ошибке `fail` возвращает кредиты) и `workflows/turbo/steps.ts` (шаги, тонкие обёртки). В `src/lib/turbo/`: `library.ts` (библиотека как файловая система только для чтения), `ops.ts` (чтение для агента с превью WebP до 1024 px через `Bun.Image`, проверка аргументов, рисование), `tool-defs.ts` (описания инструментов), `agent-definition.ts` (`createTurboAgent`, общий для воркфлоу и `eval-turbo.ts`; остановка по `acceptedImage`, `tooManyRejections` и `TURBO_MAX_STEPS`), `codex-agent-model.ts` (модель с протоколом сериализации Workflow: в журнал уходит только `modelId`, токены читаются из базы внутри шага), `workflow-runtime.ts` (окружение шагов; тесты подменяют через `setTurboRuntime`), `failure.ts` (коды сбоев данными: код едет в начале текста ошибки, свойства ошибки не переживают границу шага), `start.ts` и `start-deps.ts` (приём запуска), `codex-auth.ts` и `codex-images.ts`. Инструкция агента — `src/lib/prompts/turbo.system.ts` (`buildTurboSystem(tree)`), общие блоки канона с обогащением лежат в `src/lib/prompts/canon.ts`; хеш инструкции (без дерева) пишется в `generations.style_version`
- Отбор входных изображений: только то, что запрос называет прямо или подразумевает. Обобщённые слова про людей («богема», «свита», «стримеры») — это запрос о конкретных людях из `личности`: агент читает описания (в них сказано, кто к какой компании относится) и прикладывает 2–4 портрета, а не рисует безымянную массовку. Образ Пятёрки выбирается по ситуации запроса: названия файлов в `пятерка` показывают, для какой ситуации каждый годится; названный образ («в костюме со Slay») берётся по имени файла, а если запрос образ не назвал — агент отбирает по названиям 2–3 кандидата, открывает их (`readFile`) одним раундом и выбирает глазами; «простой» бытовой снимок берётся, только когда запрос просит обычного героя. Описания не пересказывают, как выглядит снимок: вид узнаётся из самого изображения. Картинок «от себя» — свиты, реквизита, сюрпризов — в `images` нет: они живут текстом промпта. Тест-страж на кавычки: точный текст уходит генератору с прямыми кавычками (`toGeneratorQuotes` в `drawImage`, `src/lib/turbo/ops.ts`)
- Творческое направление: инструкция Турбо (`src/lib/prompts/turbo.system.ts`) написана связной прозой, без пронумерованных правил и выкриков ALWAYS/NEVER, по образцу инструкций крупных сервисов: роль → что такое 42 → как придумывать кадр → рабочий цикл → верность запросу → библиотека → промпт для генератора → инструменты → особые запросы → примеры → самопроверка → дерево библиотеки. Дерево стоит в самом конце: всё до него одинаково для всех запросов, поэтому провайдер кэширует эту часть, а хеш версии (`generations.style_version`) считается по инструкции с пустым деревом. Агенту нужно **понимание направления, а не набор атрибутов**: раздел «Что такое 42» рассказывает, что это за сообщество (вокруг Пятёрки/Босса, взводы и батальоны, пресейвы Magnum/Opus, премия SLAY) и как выглядит визуальный язык картинок сообщества (сверка по 25 кадрам `docs/42_images/` и подборки `at42`, разбор в `docs/superpowers/specs/2026-10-10-turbo-reference-gap.md`): праздник вокруг пустяка, раздутый до эпоса; сюжет, место, жанр и цвет у каждой картинки свои, общий язык: **знакомое место, безумие в нём** (двор, класс, деревня, казарма, площадь, сцена; выдуманный мир только когда он и есть шутка), **герой-владыка** на наряженной ездовой махине, **братуха-лоск** на каждом своём, включая зверей (меховая шуба, золотая цепь с кулоном 42, тёмные очки, кепка с банданой, джерси, кроссовки; в версии под образ, а не одним набором), **42 крупно и по-спортивному** (число как номер на джерси высотой с торс на груди, решётке трактора, шарах, ящиках, камне; мелкий медальон не считается), **хайп в лицах и телах** (рты открыты, кулаки, палец в камеру), **блеск и зрелище** (золотая и хромированная техника, лазеры из глаз, фейерверки, конфетти), **размножение** (один образ до горизонта и роем в небе, различия в цвете меха и мелочи), **упаковка в жанр и реальные вещи** (Fairy, JBL, «Роллтон», Adidas; фирменная надпись на вещи часть вещи) и **свои шутки племени** (солнце и деревья с лазерами, корова в пиксельных очках). Язык обязателен, меняется его версия; сюжетные вещи словаря (мопс, самокат, диско-шар, золото) если сваливать вместе в каждый кадр это штамп. Идею агент придумывает сам: пять-восемь кардинально разных идей (свой приём, герой, место и жанр у каждой), выбирает между ними `random`, одна фраза «кто, что делает, где, в чём шутка», приёмы поиска шутки (буквально, ритуал, техника с характером, роли наоборот, масштаб, торжество не там); подробный запрос уже содержит идею, её не заменяют, а доводят. Квот и каталогов обязательных существ нет; у каждой детали должен быть ответ «что она делает для шутки», у каждой находки облик из материала, действие и место. **Штамп** назван набором, а не запретом: мопсы в шубах, диско-шар, самокат или квадроцикл, золотой трактор, горы золота, трон и корона, фейерверк, петух и бегемот вместе допустимы, только если их просит запрос или в них сама шутка; штамп бывает и в сюжете («пустяк вызвал всеобщую спасательную операцию»). Узнаваемость проверяется вопросом «если закрыть числа, флаги и надписи, это всё ещё 42: событие огромное, настроение хайп, свои в пёстрой одежде, цвет и свет громкие?». «Верность запросу» Турбо пишет сам: общий блок `CANON_FIDELITY` остался только у обогащения Krea/Ideogram. Случайных якорей в сообщении агента нет (`buildUserMessage(input, null, …)`), а строка про запрос без текста своя (`NO_TEXT_LINE` в `src/lib/turbo/agent.ts`): число 42 только там, где ему есть естественное место, один-два раза, иначе агент расставлял его по плану в каждом кадре. Проверка направления: `bun scripts/eval-turbo.ts` на разных запросах (без рисования это почти не тратит лимит подписки) и подсчёт штампов и видов зверей в итоговых промптах; примеры инструкции не должны совпадать с запросами набора проверки, иначе агент копирует свой пример. Результаты итераций: `docs/superpowers/specs/2026-10-07-turbo-creative-direction-design.md`
- Критерии готового кадра в инструкции Турбо (`# Критерии готового кадра`, `src/lib/prompts/turbo.system.ts`) написаны от слабых мест, найденных прогонами и сравнением с эталонами, а не от числа людей (толпа нормисов получается сама, и она не безумие): **несочетаемость** (у каждой фигуры своё дело, не связанное с главным событием и соседями; ожидаемые пары вроде «крот-строитель» не считаются; проверка по одной фигуре), **эпатаж** (нарушены несколько правил сразу: масштаб, физика, роль, место; серьёзность растёт вместе с абсурдом; предметы из «не того» материала, у которого есть причина в замысле), **насыщенность** (три плана с отдельным сюжетом, у света есть источник и воздух, который его показывает, палитра выводится из мира идеи и не берётся из привычного закатного неба, нет тусклых зон и пустых мест, каждая вещь фирменная, один герой позирует в камеру), **проработка** (облик, действие, место у каждой находки; причина и след события; группы разобраны по одному), **реакция зрителя** (первая секунда, пересмотр, вопрос «что там происходит?»). У агента нет памяти между запросами: ссылок на «прошлые картинки» в инструкции нет (тест-страж), разнообразие между запросами (и между прогонами одного запроса) даёт **инструмент `random`** (`src/lib/turbo/random.ts`, `pickRandom`): список вариантов на вход, один случайный элемент на выход, меньше двух вариантов — `ok: false`. Раздел инструкции `## Решает случай`: сначала агент придумывает пять-восемь кардинально разных идей и разыгрывает их одним вызовом (если идея дана в запросе, разыгрываются способы её довести), затем под выпавшую идею сам придумывает десять-двадцать решений кадра (место, время суток, цвет, жанр, основа наряда, махина, вселенные мешапа, вторая группа, ракурс…) и разыгрывает каждое своим вызовом в одном раунде; выпавшее не переигрывается, названное пользователем не разыгрывается. Причина: выбирая сам, агент на один вход давал одну и ту же идею («смысл жизни» дважды подряд стал древесным великаном) и одни и те же решения (корона 6 из 6, бархат 5 из 6). Варианты одного решения различаются **видом, а не оттенком**: прогон «виндовс 42 против линукс» дал пять мест «снежный перевал, замёрзшая станция, ледниковый овраг, снежная взлётка, ледяной мост» и четыре палитры, и все со льдом, то есть кубик выбирал между сортами одного (доля холодных слов в вариантах 45–79%). Причина в теме (Linux пингвин, пингвин лёд; Windows синий; сервер стекло и хром) и в нашей инструкции: идея включала место и жанр (выпавшая «снежная» идея красила весь кадр), а правило чистого кадра называло лёд. Поэтому: идея это приём, герой, действие и шутка, а место, время суток, цвет и носитель разыгрываются отдельно; в каждом списке один-два варианта против тяги темы; холод назначается идеей, а не тягой темы. Инструмент без `"use step"`: `Math.random()` в воркфлоу зависит от зерна прогона (документация `workflow`, `foundations/workflows-and-steps.mdx`), поэтому у прогонов разный выбор, а воспроизведение прогона даёт тот же; в тестах источник подменяется (`createTurboAgent({ random })`). Выпавшее видно в `run.randomPicks` и в выводе `eval-turbo.ts`, в базу не пишется. Большой словарь знаков `# Словарь 42` (одежда, техника, миры, существа, зрелище, вещи) остаётся источником слов для вариантов. Столкновение разных миров в одном кадре как обязательный критерий не вводилось: решение владельца. Надписи в кадре: с 2026-10-10 по решению владельца слова в запросе писать не нужно («Пятёрка и Дерзко дают концерт, пока Генсуха завидует»), реплики и плакаты придумывает агент сам, когда их требует сцена: до трёх коротких фраз по одной-четыре слова, в голосе говорящего (недруг ворчит, свои ликуют) и на своём носителе (облачко, баннер, вывеска); когда слова сцене не нужны, в кадре ни одной буквы; точный текст пользователя в кавычках по-прежнему дословно (это касается только Турбо, обогащение Krea/Ideogram работает по прежней политике). `NO_TEXT_LINE` в `src/lib/turbo/agent.ts` теперь «TEXT: not specified…»; кириллица в плакатах у генератора иногда плывёт (буква в слове), поэтому фразы короткие
- Образ героя в инструкции Турбо описан карточкой персонажа, а не словом («кот», «рыбак» без карточки пустое место): кто он на самом деле и в чём его необычный концепт, повадка и вайб, во что одет сверху вниз и почему именно так, что в руках и как делает, где на нём знак сообщества. **Одежда на языке племени в версии под образ** (меха, цепи, очки, джерси, кроссовки, пайетки), у героя запроса из статуса владыки, а не из профессии или бытового дела (при «обычном будничном дне» агент одел героя в фартук и тапки; героя наряжает статус, дело остаётся бытовым), и не из общей «коробки смешных материалов»: пока в примерах инструкции повторялись дуршлаги, самовары, прихватки, губки, пена и закатное розово-фиолетовое небо, у всех кадров была одна одежда и один цвет (замер на шести запросах: розовый, фиолетовый, оранжевый и бирюзовый в 6 из 6 промптов, губки в 6 из 6, дуршлаг в 5 из 6). Когда подсказку «одежда из мира идеи» усилили, ушли в латунь, бархат и броню (11 из 11 промптов), без мехов, очков и крупных номеров: язык племени нельзя вытеснять «исторической» одеждой. Поэтому инструкция не содержит ни списков материалов и палитр, ни квот (число слоёв, предметов, цветов), а примеры не делят общих материалов и цветов и показывают очки, цепи и крупный номер (тест-страж `turbo-prompt.test.ts`). **Уличный тест**: одна цветная вещь («фиолетовая форма», «красная лента», «синий пиджак») одеждой не считается, и слова «обычный», «простой» в карточке героя не нужны даже при просьбе об обычном (повод бытовой, а выглядит герой так, что его не пропустить). **Ничего по умолчанию**: всё названное, но не описанное, генератор достраивает самым средним вариантом (замок из серого камня, серый асфальт, голубое небо), поэтому у каждого существительного кадра есть материал, цвет, состояние и странность, фон описан как герой. **Каждая вещь фирменная**: знак сообщества (число 42, корона, лавровый венок, цепь с кулоном, нашивка взвода) стоит на технике, одежде, предметах, а не только на герое, число пишется крупно и по одному на предмет (мелкие цифры генератор путает); строка про запрос без текста `NO_TEXT_LINE` в `src/lib/turbo/agent.ts` не ограничивает число знаков. Ездовая махина и главная вещь сюжета наряжены не беднее хозяина. Публика жанра (красная дорожка, парад) одета в безумный стиль жанра, обычные люди одним-двумя со странным делом. **Как собирается безумие** (отдельный раздел инструкции, по разбору `docs/42_images/Фантастический парад черепашьего босса.png`): наращивание (основа и четыре-шесть надстроек разных категорий с экипажем: черепаха → бронированная → огнедышащая → в очках → с шипами → с пушками → пушками управляют мопсы → мопсы в костюмах), рекурсия (надстройки раскрываются на третий уровень), превосходная степень внутри вещи («скипетр из всех драгоценностей мира»), сломанная логика (бриллианты стреляют лазерами из глаз), массовка из комбо (существо + транспорт + лоск + 42) и подчинение всего идее; агент сначала строит в уме дерево наращивания, потом пишет промпт по веткам. Прогон «Пятёрка и Дерзко дают концерт, пока Генсуха завидует» (аниме-постер, жирафы на самокатах с 42, Генсуха в окне диспетчерской среди серых сумок) выявил ещё пять поправок, внесённых в инструкцию: (1) костюм с входного изображения агент пересказывал («чёрно-белый костюм Слэя… накидка с одной стороны, крыло с другой»): он остаётся как на картинке, пишутся только изменения и дополнения; (2) придуманная реплика вышла по-английски («Must be nice!»): слова пишутся на языке запроса; (3) в концерте не было публики: зал есть в кадре у концерта, премии, парада, матча, выступления и митинга, даже если запрос о нём молчит; (4) Генсуха вышла мелкой в окне далёкой башни: «другой уровень» значит отдельно от сцены, а не далеко и мелко, недруг занимает не меньше шестой части кадра (врезка, экран, край переднего плана); (5) фигуры мелкие при уйме свободного места: герои и названные предметы вместе занимают не меньше двух третей кадра, свободное место значит «приблизь камеру». Четвёртый прогон концерта (комикс-обложка, Пятёрка в космическом пирате, бегемоты на самокатах с RGB-цепями, Генсуха во врезке) дал размеры и Генсуху на месте, и три оставшиеся поправки владельца: (1) зал стал тёмными силуэтами: агент сжал «зал» до одного поклонника на клавиатуре (все четыре варианта розыгрыша «зала» были про одного человека, а лазейка «людей столько, сколько можно описать» позволяла это), остальное генератор дорисовал сам силуэтами; теперь зал это группа людей, силуэты, поднятые руки без людей и спины запрещены, в промпте сказано «the audience is individually dressed people lit by the stage, not silhouettes», зал разыгрывается как тема образа всей публики (светящиеся шарфы, шапки-еда, маски с лазерными глазами), а каждого человека внутри темы агент пишет сам; (2) реплика Генсухи «ОПЯТЬ ОН!» общая (годится в любой кадр): реплика колет точное в этой сцене голосом именно этого человека (для человека из библиотеки голос берётся из его описания), общие восклицания запрещены, пример в инструкции заменён (прежний «Генсуха завидует» совпадал с запросом проверки); (3) приём «малое становится миром» по эталону `Коронованный кибернетический страж под водой(1).png` (на каждом погоне гоночная трасса с электросамокатами, дирижабль несёт голограмму, на которой стоит ноутбук, RGB-трубки вместо проводов, боксёрские перчатки в цветах 42, майнкрафтовская мордочка на мозге): минимум одна малая деталь героя и одна главного предмета вырастают в сооружение с отдельной жизнью; обязательное решение розыгрыша; эталон назван не для копирования. Третий прогон концерта (космический лифт, аниме, зал из Яйцафонка и Валеры Вишни, Генсуха в экране с русской репликой) показал: фон занимал около половины кадра (идея про огромное место, генератор сам выбирает масштаб и отодвигает камеру, если про него не сказано), поэтому в промпте теперь называется план («tight medium shot from the chest up»), обрезка краями кадра и голова героя не меньше восьмой части высоты, огромное место показывается фрагментом, а пустых участков нет вовсе (проверка девятью частями кадра: в каждой что-то крупное); реплика Генсухи занимала около одного процента кадра: слова крупные, облачко от шестой части ширины кадра, плакат от трети, размер называется в промпте; Пятёрка осталась с костюмом со Слэя и микрофоном («оставить как есть» агент понял из правила не пересказывать): дополнений у героя с входного костюма не меньше двенадцати новых вещей. Счёт вещей 12/8/4 остаётся, но с мерой качества (2026-10-10): на концерте по референсу агент выполнил его перечнем общих украшений через запятую (Пятёрка: двенадцать вещей в одном предложении на 98 слов, «jeweled gloves», «a laurel pin»), а на всю публику ушло 25 слов из 867. Моё первое решение «меньше вещей, но глубже» владелец отверг как компромисс: нужны и больше вещей, и глубина. Поэтому вещь считается, только если это «узнаваемое плюс поворот» в две-шесть слов (узнаваемая вещь из чужой вселенной, эпохи, профессии или бренда, либо обычная вещь с абсурдной поправкой; двенадцать вещей по пять слов это шестьдесят слов); вещи без поворота вычёркиваются. Слова распределяются по смыслу (герои, публика, названные предметы и недруг не меньше, чем площадка и свет, а при нехватке сокращается площадка; восьмисот слов хватает), оговорка точности «exactly as in Image N» пишется один раз на всех людей. Референсы сообщества делались короткими промптами и всё равно лучше наших: длина не даёт качества, его даёт плотность поворотов. Герой собран минимум из трёх узнаваемых источников (мешап из игр, аниме, фильмов, мемов, брендов, фольклора). **Крупно, а не много**: кадр держат около шести крупных проработанных объектов (герой с махиной, две-три группы второго плана, противник, одна масса из повторов одного образа или рой крупных шаров-цифр); безымянные толпы, стаи мелких птиц и россыпь крошечных фигурок запрещены, они дробят кадр (прогон, где агент гнался за количеством, дал именно это). **Лоск не форма**: у лоска десятки основ (джерси, шуба, пиджак с монограммами, худи, костюм с банданой, джинсовка, латы, скафандр…), основу подсказывает идея по образцу эталонов, а «герой владыка» значит поза, размер и свита, а не костюм короля; «шуба поверх джерси с 42 и кепка с банданой», горностаевая мантия с короной, двор панельного дома, латунь, стимпанк, самурай и визор скафандра названы штампами (замеры: джерси и латунь в 7 из 7 промптов, затем мантия с короной в 6 из 6, когда мантия стояла первой в списке основ; корона и венок только для побед и коронаций). **Цветовой замысел**: один-два господствующих насыщенных цвета, контрастный акцент и глубокие тени, драматичный свет; бледные пастельные, мятные и бежевые площади запрещены (жалоба владельца на «зелёно-бежевую» гамму); на эталонах дневных и ночных кадров примерно поровну, и ночь с малиновым и тёмно-синим такой же штамп, как бежевый день; палитры примеров разные, красный и синий не больше чем в двух (тест-страж: красный в палитрах шести примеров давал красно-синий в каждом кадре). Образец плотности в инструкции это пример 6 («записался в спортзал»: тема нарочно далека от набора проверки, вещи примера помечены как непереносимые, потому что прежний пример 6 про права агент растаскивал по чужим кадрам). Размер промпта 550–800 слов, пять-семь абзацев по веткам (на 1000+ словах рисование доходило до 244 с при лимите 270 с). Запросы набора `scripts/eval-turbo.ts` не должны совпадать с примерами инструкции: агент копирует свой пример
- **Противостояние «X против Y»** (рабочий пример «виндовс 42 против линукс»; референс `docs/42_images/Batalha épica na cidade destruída.png`: вилтрумит с логотипом Windows, сеструха в костюме из игральных карт с клоунским гримом, братуха в жёлтом костюме с бабочкой и золотым плащом, Пятёрка в перерисованном в безумном стиле костюме со Слэя нападают на пингвина Linux, комикс). Что выяснили прогонами и записали в инструкцию: сторона 42 это люди из библиотеки (`пятерка`, `личности`), а не безликая армия; бренд становится стороной через логотип (самая узнаваемая, обычно классическая многоцветная версия в фирменных цветах, описанная по частям: форма и каждый цвет на своём месте, потому что «логотип X» генератор рисует приблизительно, а одноцветный синий Windows сливался с палитрой кадра) и талисман; это схватка трёх-пяти крупных героев на одного крупного противника, а не осада с крепостью, дирижаблем и десятками пингвинов; композиция читается за секунду (одна точка события, стороны разведены, фон тише героев, расстановка слева/в центре/справа названа в промпте); носитель разыгрывается (фото, 3D, комикс, аниме-постер, обложка игры), а не всегда фото; каждый человек из `images` в кадре ровно один раз (безымянных «братух в кабине» генератор рисует теми же лицами с портретов); для громкой сцены берётся снимок Пятёрки в ярком образе (костюм со Слэя), а не обычное фото «по колено», с которого генератор переносит и будничный вид; у героя в карточке концепт костюма с названным источником, а не «стритвир» и «пальто в пайетках». Пример в инструкцию не вписан (агент копирует свои примеры), он живёт в `scripts/eval-turbo.ts`.
- **Концерт сообщества по референсу** (рабочий пример «Пятёрка и Дерзко ведут концерт для 42-братух, злая Генсуха кричит «Я ненавижу творческих 42», а над сценой самолёт из Minecraft Create тянет плакат «Богема, хватит доедать»»; референс `docs/42_images/Fête surréaliste sous les feux d'artifice.png`: ночной стадион, фейерверки 42, жирафы и бегемоты в цепях 42 на самокатах, Пятёрка и Дерзко в центре, злая Генсуха крупно на переднем плане, самолёт Minecraft Create с плакатом, публика 42-братух в RGB-шарфах, шапках-бургерах и наушниках с бриллиантами). Первый прогон показал три провала, исправленные в инструкции: (1) публику агент заменил кубическими майнкрафтовскими аватарами («no extra realistic human faces»): моё правило «безымянные фигуры либо не люди, либо другие люди» он выполнил буквально, а тема Minecraft от самолёта растеклась на будку, луну и толпу. Теперь безымянные люди показываются со спиной, в профиль или с лицом под частью костюма, заменять их аватарами нельзя, вселенная названного предмета остаётся на нём; (2) публика сообщества это крупные люди, и у каждого видимого человека свой отличающийся проработанный образ со знаками 42-стиля, описанный отдельной фразой (квоты на число людей нет: владелец поправил «не меньше пяти», лучше меньше людей, но прописанных глубоко, чем много с общим «одеты в куртки»; если не хватает места, людей в кадре становится меньше, а не образы мельче); «толпа кубов» и «a crowd of fans» запрещены; (3) ключевое из запроса не бывает мелким (герой от трети кадра, предмет от шестой части, текст целиком), а Генсуху розыгрыш уменьшил до фигуры в будке. Классика сообщества (бегемоты и жирафы, самокаты, RGB-подсветка, золотые цепи с 42, фейерверки в форме 42) на результатах не появлялась, потому что инструкция называла её штампом и просила не ставить в варианты: теперь это раздел «Классика сообщества», она стоит среди вариантов наравне с остальным и не занимает их все. Дерзко добавлен в `личности` (`derzko.png`: дружественный стример, не 42-братуха; 42-братухи это подписчики Пятёрки). Второй прогон: публика всё ещё одной фразой «a dense audience of back-facing 42-brothers…» при промпте 867 слов, и ни в одном из 44 вариантов розыгрыша не было классики сообщества: правила глубины и классики читаются как пожелания, их надо делать обязательными решениями. Генсуху агент одел в 42-лоск (корона-ореол, цепь, мех, блеск) и сделал поющей, на сцене на одном уровне с героями; владелец поправил: **недруги 42** (богема, хейтеры, соперники, Генсуха) злые и угрюмые, без знаков 42 и лоска, на другом уровне кадра (отдельная крупная фигура на краю переднего плана, во врезке или за пузырём реплики, как на референсе), а их богатство показывается только карикатурой («зажрались», дуреют от сумок и тачек). Правило в разделе «Как придумывать кадр» (`Недруги 42.`). И последнее замечание по самолёту Create: даже названный в запросе предмет агент делал базовым минимумом («самолёт из разноцветных блоков»), без своей задумки вокруг него. Теперь в разделе «Ездовая махина и предмет сюжета тоже образ» абзац «Названное в запросе получает роскошный максимум»: каждый названный предмет, транспорт, существо и место получает ту же полноту, что герой (цепочка наращивания, экипаж или обитатели, сверхспособность, поломка логики, знак 42 и своя отдельная мини-история с причиной, действием и следом), свой абзац в промпте и свои отдельные вызовы `random`; «чем короче названо, тем больше придумываешь ты».
- **Носитель** (фото, 3D, комикс, аниме или манга, обложка игры, плакат, живопись) разыгрывается через `random` сразу после идеи, если пользователь его не назвал; половина вариантов нарисованные. Журналы 12 запусков «виндовс 42 против линукс»: в списке носителей из 3–6 вариантов нарисован один, нарисованный выпал в 3 из 12, а и тогда кадр выходил фотографией: тело промпта (14–21 слово материалов вроде scratched, fur, chrome против 0–5 слов про тушь) и четыре «exactly as in Image N» на людях из библиотеки перевешивали слово «comic» в последней формуле. Поэтому: носитель назван в первом предложении и в формуле, текст между ними написан его словарём (контур, заливка, штриховка, без микро-материалов), а в нарисованном носителе человек из библиотеки перерисовывается («redrawn as a comic-book fighter whose face, hairstyle and build stay recognisable»), флаги и эмблемы остаются точными. В инструкции пример 7 показывает комикс с человеком из библиотеки.

- Workflow на Bun: пакеты `workflow`, `@ai-sdk/workflow`, `@workflow/serde`, `ai` закреплены точными версиями (`@ai-sdk/workflow` требует ровно `ai@7.0.133`), `@swc/core` строго `1.15.3` (под него собран плагин SWC; 1.16.x даёт «Failed to deserialize program received from host»). Код приложения преобразует плагин `workflow-transform.ts`; в разработке он подключён через `preload` (`workflow-plugin.ts` в `bunfig.toml`), в сборке для Vercel его передаёт `Bun.build` (`scripts/build-vercel.ts`). Параметры SWC повторяют сборщик Workflow (`target: es2022`, иначе классы с `"use step"` ломаются). В `bun test` плагин не применяется: воркфлоу и шаги там обычные функции, поэтому ветки ошибок проверяются юнит-тестами через `setTurboRuntime`, а сериализацию проверяет только живой прогон. Локально работает Local World (`.workflow-data/`, в `.gitignore`), порт доставки очереди `PORT=3000`; посмотреть прогон: `node_modules/.bin/workflow inspect runs`. Лимиты на Hobby: 50 000 событий и 1 ГБ записи в месяц, шаг ограничен лимитом функции 300 с; хранение прогона 1 день
- **Уровень рассуждения агента выбирает пользователь** (2026-10-10): `medium` | `high` | `xhigh` | `max`, по умолчанию `high` (`src/lib/turbo/reasoning.ts`: уровни, умолчание и `parseTurboReasoning`; модуль без зависимостей, его читают и страница, и сервер). Страница в режиме «Турбо» показывает ползунок (shadcn `Slider`, подписи «Среднее / Высокое / Очень высокое / Максимальное», выбор в `localStorage` `gen42-reasoning`), `POST /api/generate` принимает необязательное `reasoning` (нет поля — `high`, неизвестное значение — 400 «Некорректный уровень рассуждения»), `startTurbo` кладёт уровень во вход воркфлоу явно, `createTurboAgent({ reasoning })` передаёт его модели. Цена не зависит от уровня (10 кредитов), уровень в базу не пишется (миграции нет); прогоны, запущенные до выбора, идут на `high`. Замеры на запросе про концерт (один прогон на уровень, лимит подписки после каждого сдвинулся меньше процента): `high` агент 111 с, 136 тыс. токенов; `xhigh` 266 с, 201 тыс.; `max` 335 с, 210 тыс., в промпте 891, 951 и 990 слов (правило «до 950 при публике» `max` нарушил); `medium` не мерился. Модель `gpt-6.1-sol` на этих настройках за 180 с не успела (агент до рисования не дошёл, расход окна 5 часов 2%, недели 1%): на `luna` остаёмся. Сравнение уровней и моделей: `TURBO_EVAL_MODEL`, `TURBO_EVAL_REASONING`, `TURBO_EVAL_AGENT_TIMEOUT_MS` для `scripts/eval-turbo.ts`
- Бюджеты времени: агент до 500 с (`TURBO_AGENT_TIMEOUT_MS`; это не лимит платформы, а наш абсолютный срок на все вызовы модели: каждый вызов идёт отдельным шагом с лимитом функции 300 с, а общего потолка на прогон у Workflow нет, документация `worlds/vercel.mdx` и сравнительные таблицы), рисование до 270 с (`TURBO_DRAW_TIMEOUT_MS`, запрос к Codex обрывается сам раньше лимита функции); рисование без повторов (`drawStep.maxRetries = 0`): у Codex Images нет ключа идемпотентности. Шаги идут внутри уже запущенного вызова `flow`, а лимит функции считается от старта вызова, поэтому у функций Workflow задан `WORKFLOW_V2_TIMEOUT_MS=10000` (`scripts/build-vercel.ts`): после любого шага длиннее 10 с продолжение уходит в очередь и следующий шаг стартует в свежем вызове (по умолчанию для 300 с это 2 минуты, и рисование, стартовавшее на 80-й секунде вызова, платформа убила бы раньше его таймера). Сбой шага ведёт к шагу `fail` (возврат кредитов, ровно один раз), мёртвый вход Codex помечается для админки; сбои самого рантайма Workflow (`REPLAY_TIMEOUT`, `MAX_DELIVERIES_EXCEEDED`, `DEPLOYMENT_MISMATCH`, ошибка загрузки бандла) шаг `fail` обходят, и строку тогда закрывает ленивое закрытие через 12 минут

## Деплой на Vercel

- Сборка для Vercel собственная, в формате Build Output API (`vercel.json`: `framework: null`, `buildCommand: bun run build:vercel`). Пресет `framework: bun` не годится: его сборщик сам компилирует серверный код и не применяет плагин Workflow, из-за чего `start()` не получает идентификатор воркфлоу («invalid workflow function»). `scripts/build-vercel.ts` собирает сервер `Bun.build` одним файлом (`functions/index.func/server.js`, рядом `dist/`, без `node_modules`); функции Workflow (`flow.func` с триггером очереди и `webhook`) создаёт `workflow build --target vercel-build-output-api`; у всех функций `runtime: bun1.4.x`, `architecture: x86_64`, а рядом с каждой лежит `bunfig.toml` с `[install] auto = "disable"`: файловая система функции только для чтения, и Bun 1.4 при импорте несуществующего модуля запускает автоустановку пакетов, пытается записать `node_modules/.cache` и убивает процесс ошибкой «bun is unable to write files: EROFS» на первом запросе (воспроизводится локально на read-only диске: `bwrap --ro-bind / / …`); с отключённой автоустановкой это обычное исключение `ERR_MODULE_NOT_FOUND` с именем модуля. Крон из `vercel.json` Vercel добавляет в `config.json` сам (вручную туда не писать: дублируется). Каталог вывода с точки в начале (`.output`) сборщик Vercel не принимает, а `workflow build` принимает за исходники всё в папках проекта вне своего списка игнорируемых (`.vercel` в нём есть), поэтому бандл сервера пишется прямо в `.vercel/output`
- `maxDuration: 300` функции сайта записан в `scripts/build-vercel.ts`: генерация Ideogram 4 ждёт результат до 180с, плюс впереди LLM-обогащение и очередь ZeroGPU; Hobby+Fluid допускает до 300с. Уменьшать лимит нельзя без сокращения таймаутов опроса. У `flow` `maxDuration: "max"`
- Турбо не упирается в лимит одного вызова: агент и рисование это отдельные шаги воркфлоу, и благодаря `WORKFLOW_V2_TIMEOUT_MS` каждый длинный шаг стартует в своём вызове `flow` с лимитом 300 с (Hobby). В проекте Vercel должны быть включены системные переменные окружения («Automatically expose System Environment Variables»): без `VERCEL_DEPLOYMENT_ID` `start()` выберет Local World и попытается писать `.workflow-data` на read-only диск, и каждый запрос Турбо закончится ошибкой с возвратом кредитов. Замеры на dev (`bun scripts/eval-turbo.ts --generate`, до перехода на Workflow): запросы без героев 70–90 с, с четырьмя входными героями 90–420 с (рисование делает от 1 до 12 внутренних проходов по 25–35 с, число плавает у провайдера независимо от промпта; ручек качества, размера, формата, модели и `service_tier` у Codex Images нет; рассуждение агента `high` стоит 20–50 с до первого токена), см. `docs/superpowers/specs/2026-10-07-turbo-creative-direction-design.md`. Размещение обработчика очереди и результаты проверок: `docs/superpowers/specs/2026-10-08-turbo-workflow-design.md`
- Зависимости сервера сайта целиком в бандле `Bun.build`, поэтому `includeFiles` и ошибки `Cannot find package 'X'` из-за разных условий exports (старая сборка пресета) больше неактуальны. Не попадает в бандл только то, что подключено строкой, вычисляемой в рантайме (в `src/server.ts` это dev-маршрут `flow`, в продакшене он выключен)
- Локальная проверка сборки: `npx --yes vercel@latest build` (установленный CLI может быть старее схемы триггера `queue/v2beta`; в `vercel.json` триггер очереди писать без поля `consumer`, имя потребителя строит Vercel), затем из `.vercel/output/functions/index.func` запустить `PORT=3056 NODE_ENV=production bun --env-file=<путь к .env.development> server.js` и проверить `/` и `/api/models`
- **Авто-деплой**: проект подключён к GitHub (`42-Z/gen42`, прод-ветка `main`) — пуш в `main` собирает прод, другие ветки дают preview. Hobby-план не подключает приватные репо организаций, поэтому репозиторий публичный; при возврате приватности авто-деплой переносить на GitHub Actions (`vercel deploy --prod` по токену)
- Ручной выкат: `vercel deploy --prod --yes`. **Изменения env вступают в силу только после нового деплоя**
- Env переменные: не перетирать прод-специфичные значения локальными (например `BETTER_AUTH_URL` = прод-домен). Секреты Vercel помечены sensitive и не вытягиваются обратно (`vercel env pull` отдаёт `[SENSITIVE]`); добавлять/обновлять через `vercel env add NAME <environment> --force`, значение — из stdin. App-секреты дублируются в GitHub Actions secrets (`gh secret set -f <file>`)

## Процесс изменений (обязательно)

- **Документация направляет каждый этап работы**: проектирование, реализацию, отладку, проверку и наблюдение за поведением. Перед каждым шагом читать документацию версии, которая стоит в проекте (для AI SDK — скилл `ai-sdk` и `node_modules/ai/docs`; для остального — официальные доки и скиллы), и делать так, как она описывает, а не минимально рабочим костылём из памяти. Нужна возможность, которой нет в коде, — сначала искать штатный механизм (например, колбэки жизненного цикла и `result.steps` агента вместо самодельных обёрток), и только если его нет — решать иначе и говорить об этом явно
- **Плюсы и минусы вариантов — только по фактам.** Каждое утверждение о варианте опирается на источник: страницу документации версии проекта или результат проверки на деле. Отсутствие примера или упоминания в документации — не минус и не риск, а статус «не проверено»: он записывается отдельно и закрывается проверкой, а не снижает оценку варианта. Минус — измеримая цена: что сломается, сколько работы, денег, времени или лимита. Разовая правка кода, конфигурации или переменных окружения минусом не считается. Варианты сравниваются по полной цене, включая код, который придётся писать и поддерживать самим (самодельный механизм не «проще», чем штатный механизм платформы). Осторожность без данных не причина отвергать вариант или рекомендовать другой: нет данных — сначала проверка, потом рекомендация. Вывод о варианте формулируется как «подтверждено», «не проверено» или «опровергнуто» с источником
- **Коммиты — по ходу работы, без отдельной просьбы владельца.** Законченные логические единицы (скилл, спека, фича с тестами) коммитятся на рабочей ветке, не в `main`; сообщение по-русски, в духе истории репозитория. Артефакты прогонов (`docs/evals/*.jsonl`, `captures/`) в коммит не попадают без просьбы. Пуш, PR и всё, что касается `main` и прода, по-прежнему только с разрешения владельца
- `AGENTS.md` и `README.md` — живые документы: обновлять их регулярно, в каждой работе, которая меняет поведение, контракты, стиль, схему БД, переменные окружения или договорённости с владельцем (включая его правки и пожелания, высказанные в ходе работы). Устаревшая строка в этих файлах — такой же брак, как баг в коде

- Перед PR обновлять `AGENTS.md` и `README.md`, если изменились поведение, контракты, схема БД или переменные окружения
- Перед PR прогонять свежие проверки: `bun run typecheck`, `bun run lint`, `bunx biome format .`, `bun test`, `bun run build` (плюс `vercel build --prod` при изменениях серверной части и зависимостей)
- Перед PR делать ревью диффа (субагент-ревьюер): находки blocker/major закрывать до мержа, minor — осознанно принимать или закрывать
- Не заявлять о готовности без свежих свидетельств (verify-before-completion): команда, её вывод, только потом вывод о результате
- **Предсуществующие ошибки и предупреждения исправлять по ходу.** Если линтер, тайпчек или тесты ругаются на код, который ты трогаешь (или рядом), — починить в рамках этой же работы, а не оставлять со словами «это было до меня». Исключение — правка явно вне зоны задачи; тогда вынести отдельно
- **В описании PR не писать про запуск линтера, тайпчека и тестов** — это не интересно ревьюеру. Вместо этого, если были изменения фронтенда, вставить в описание PR скриншот (через скилл `before-and-after`, не ссылкой на временный хостинг)
- Мерж в `main`, миграции прод-базы, ключи и любые действия на проде — только с явного разрешения владельца; `main` защищён, изменения идут через PR с зелёным CI
- Скиллы — часть репозитория: `.agents/skills/**` (содержимое), `.claude/skills/**` (симлинки на них) и `skills-lock.json` коммитятся вместе с изменениями, а не остаются локальными
