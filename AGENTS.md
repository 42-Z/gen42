# AGENTS.md

Инструкции для агентов, работающих с этим репозиторием.

## Главный принцип продукта

По простому промпту приложение делает «42-безумие», но **никогда не упускает задумку, которую написал пользователь**: героя, действие, место, цвета и текст. Задумка остаётся центром кадра и лишь пропитывается 42-вайбом — пёстрыми образами, свитой, роскошью, числом 42. Обилие 42 без просьбы — норма; ошибка — только подмена или потеря замысла. Эталон стиля — картинки сообщества в `docs/42_images/`: сверяйся с ними, когда меняешь промпт улучшателя.

## Стек и конвенции

Везде используем Bun вместо Node.js:

- `bun <file>` вместо `node`/`ts-node`
- `bun test` вместо jest/vitest
- `bun install`, `bun run <script>`, `bunx <package>`
- Bun сам загружает `.env` — dotenv не нужен
- Нужен Bun не ниже 1.4.2. Корневой `bunfig.toml` подключает плагин Workflow (`preload`), и в Bun 1.4.0 его `onLoad` получает испорченный путь, если в пути проекта есть не-ASCII символы (у владельца это «Рабочий стол»): `bun файл.ts` падает с ENOENT. `bun run <script>` берёт Bun из `node_modules/.bin` (1.4.2) и работает; для прямого запуска вне скриптов использовать `node_modules/.bin/bun файл.ts` или обновить глобальный Bun
- В коде, достижимом из шагов Workflow (`workflows/**`, `src/lib/**`), не писать `import … from "bun"`: сборщик Workflow бандлит шаги esbuild и не разрешает этот импорт в финальном бандле. Использовать глобальный `Bun.*` (например, `new Bun.S3Client(…)` в `src/lib/storage.ts`)

Разовые скрипты на Python запускать через `uv run`, в том числе inline:

```bash
uv run - <<'EOF'
print("hello")
EOF
```

`--no-project` добавлять только когда в директории есть `pyproject.toml` и проект не нужен. Никаких `python3 -c` напрямую.

API:

- `Bun.serve()` с `routes` — никаких express/fastify
- `postgres` (postgres.js) для Postgres через `src/lib/db.ts` — не смешивать с `Bun.sql`
- `Bun.s3` для хранилища — не тянуть aws-sdk
- `Bun.file` вместо `node:fs` readFile/writeFile

Фронтенд:

- HTML imports: `index.html` в корне импортирует `./src/frontend.tsx` и `./src/index.css`, Bun bundler собирает сам. Vite не использовать
- Сервер отдаёт статику из `dist/` (см. `src/server.ts`)

## Архитектура

- `src/server.ts` — основной entrypoint: API-роуты (`/api/auth/*`, `/api/attachments/sign`, `/api/attachments/complete`, `/api/generate`, `/api/generations`, `/api/generations/active`, `/api/generations/running`, `/api/generations/:id`, `/api/generations/:id/thumb`, `/api/generations/:id/preview`, `/api/generations/:id/download`, `/api/me`, `/api/models`, `/api/admin/*`, `/api/cron/*`) + раздача `dist/`. Обработчик очереди Workflow (`flow`) локально монтируется в этот же сервер (`/.well-known/workflow/v1/flow`, только вне продакшена); на Vercel это отдельная закрытая функция `.well-known/workflow/v1/flow.func` из `bun run build:vercel` (триггер очереди пишет `workflow build`)
- `src/lib/models.ts` — реестр движков генерации `IMAGE_MODELS` (krea / ideogram): адрес Space, стоимость в кредитах, таймаут; «Ультра» описан отдельно (`ULTRA_MODEL`, 10 кредитов, без Space); `publicImageModels({ ultra })` отдаёт только `id/label/cost` и при рабочем входе Codex возвращает канонический `ultra` вместе с `turbo` как алиасом для уже загруженных старых интерфейсов
- `src/lib/llm.ts` — единый клиент LLM-провайдеров: реестр `LLM_PROVIDERS` и generic `callLlm({ provider, … })` на AI SDK v7 (`ai` + `@ai-sdk/openai-compatible`)
- `src/api/` — обработчики роутов; `src/lib/` — доменная логика (credits, keys, models, hf, llm, enhance, storage, rate-limit); `src/lib/prompts/` — промпт-инженерия стиля «42»
- Ключи всех провайдеров живут только в таблице `api_keys` (`provider`: `huggingface` | `poolside` | `inception`) и управляются через админку (`/api/admin/keys`: добавление, проверка, удаление; `?provider=` выбирает список). В env и файлах они не хранятся, API отдаёт их маскированными
- Баланс пользователя: генерация списывает стоимость движка из `IMAGE_MODELS` (Krea 2 — 1, Ideogram 4 — 3, «Ультра» — 10) — `src/lib/credits.ts` (`deductCredits`/`refundCredits`). Новому пользователю при регистрации даётся 42 кредита (`grantSignupCredits`, hook `databaseHooks.user.create.after` в `src/lib/auth.ts`; константа `SIGNUP_BONUS_CREDITS` = `DAILY_GRANT_CREDITS`)
- Ежедневная выдача: крон Vercel (`vercel.json` → `crons`, `0 21 * * *` = 00:00 МСК) бьёт в `GET /api/cron/daily-credits`, секрет — `Bearer CRON_SECRET` (переменная `CRON_SECRET` в Vercel; без неё роут отвечает 401). Начисление — `grantDailyCredits()` в `src/lib/credits.ts`: один атомарный SQL, `+42` (`DAILY_GRANT_CREDITS`) каждому, у кого строки `credits` нет или `last_grant_date < сегодня (МСК)`; идемпотентно (повторный вызов за день — 0), гонка двух одновременных вызовов закрыта `IS DISTINCT FROM` в `DO UPDATE`. Hobby-план запускает крон «внутри часа» — выдача приходит между 00:00 и 01:00 МСК, а не ровно в полночь; Vercel не ретраит упавший крон — пропущенный день значит потерянную выдачу для всех (догонок нет, защита от дублей есть). Неактивные пользователи копят 42/день без ограничений — осознанно
- Первый пользователь с email из `ADMIN_EMAIL` — админ

## Хранилище (S3)

- `src/lib/storage.ts` использует `Bun.s3` (`S3Client`). Env: `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_ENDPOINT`, `S3_BUCKET`, `S3_REGION`. Bun по умолчанию ходит path-style, что и требуется S3-совместимым провайдерам
- Прод — единый Neon-проект `gen42-storage` (`rapid-water-10723622`, `us-east-2`, ветка `main`): и Postgres (`neondb`), и **Neon Object Storage** (бакет `images`, private, чтение через presigned URL). Старый проект БД `gen42` (`steep-block-68050198`, `us-east-1`) не используется — данные переехали 2026-09-15 (pg_dump/restore, сверены md5 всех 7 таблиц)
- Локальная разработка — ветка `dev` в том же проекте (копия `main`, свой изолированный бакет). `bun dev` подхватывает `.env.development` (dev-DATABASE_URL + dev-S3), продовый `.env` не трогает; `NODE_ENV=production` берёт прод
- S3-креды Neon **branch-scoped** и выдаются так (запускать из `/tmp`: `--file` не принимает абсолютный путь):

  ```bash
  neon env pull --file storage.env --project-id rapid-water-10723622 --branch main -s object-storage
  ```

  Затем разложить `AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY/AWS_ENDPOINT_URL_S3/AWS_REGION` → `S3_*`. `env pull` выдаёт новую пару ключей; после ротации перезалить их в Vercel и GitHub. Смена кредов вступает в силу только после редеплоя

## Превью изображений (галерея)

- Сетка «Недавние» грузит не оригиналы (PNG до нескольких МБ, пресайн S3 с новой подписью на каждый запрос, то есть без кеша браузера), а WebP-превью до 640 px по длинной стороне (`src/lib/thumbnails.ts`, `Bun.Image`), ключ `thumbs/<ключ оригинала без расширения>.webp` в том же бакете
- Для просмотра и готового результата под полем используется отдельный WebP размером до 1600 px по длинной стороне и с качеством 90; ключ включает полный ключ оригинала: `previews/v1/<ключ оригинала>.webp`, чтобы разные исходные расширения не сталкивались. Оба варианта создаются независимо при сохранении картинки (`storeThumb` в `store` попытки Krea/Ideogram и `storeImage` режима «Ультра»); сбой не мешает сохранить оригинал или второй вариант. Для старых изображений копии создаются лениво при первом запросе и сохраняются
- `GET /api/generations` отдаёт стабильные адреса `thumb_url` и `preview_url` (`/api/generations/:id/thumb` и `.../:id/preview`) и presigned `image_url` для оригинала. Доступ к обеим копиям и `/api/generations/:id/download` проверяется по сессии и владельцу; неизменяемые изображения кешируются в браузере как `private, max-age=31536000, immutable`. Просмотр использует preview WebP и показывает исходный промпт, движок и модель, разрешение, длительность и сохранённый reasoning (для старых записей поле не задано); «Скачать» потоково отдаёт оригинал без перекодирования

## Генерация (HuggingFace)

- Krea 2 и Ideogram 4 идут воркфлоу Vercel Workflow (`workflows/spaces/`, логика попытки и ротации ключей в `src/lib/spaces/`), как «Ультра»: `POST /api/generate` создаёт строку `running`, списывает кредиты, стартует воркфлоу и сразу отвечает `202 { id, engine, cost }` (общий приём `src/lib/start-run.ts`), страница ждёт опросом `/api/generations/:id`. Шаги: `enhance` → `generate` (одна попытка: ключ HF, Space, скачивание, картинка и превью в хранилище, квота ключа; `maxRetries = 0`, потому что каждый вызов расходует прогон ZeroGPU) → `complete`; любая ошибка → `fail` с возвратом кредитов ровно один раз. Цикл до 5 попыток (`key_exhausted` исключает ключ, `queue_timeout` повторяет тот же, нет ключей или прочая ошибка завершают запуск) живёт в коде воркфлоу (`runWithRotation`), новые попытки не начинаются позже 10 минут от старта (`SPACE_RUN_DEADLINE_MS`); порядок «худший прогон < ожидание страницы < закрытие зависших» держит `ultra-budgets.test.ts`. Коды сбоев в истории прежние: на практике приходят `all_keys_exhausted` и `error` (остальные исходы попытки воркфлоу повторяет). Krea и Ideogram теперь зависят от Workflow и очереди Vercel: при их недоступности запуск закрывается с возвратом кредитов (502)
- `src/lib/hf.ts` — общий Gradio-клиент `callSpace()`: `POST {space}/gradio_api/call/v2/{api}` (payload именованными полями, без старого `data: [ {…} ]`, иначе `event: error`), затем опрос `…/call/v2/{api}/{event_id}` с фолбэком на `…/call/{api}/{event_id}` при 404. Ответ: `data[0].url` (картинка), `data[1]` — seed. Движки задаются реестром `IMAGE_MODELS` (`src/lib/models.ts`), `generateImage({ engine, … })` диспатчит по нему
  - **Krea 2** — `krea-krea-2.hf.space`, поля `prompt/negative_prompt/model/steps/guidance/width/height/seed/randomize` (model `Turbo`/`Raw`, guidance 0, steps 8)
  - **Ideogram 4** — `ideogram-ai-ideogram4.hf.space`, поля `prompt/mode/upsampler/width/height/seed/randomize_seed`. Режим фиксирован `Default · 20 steps`, апсемплер `Ideogram (remote)` (Space сам фолбэчит на локальный Qwen); negative prompt и `model` Ideogram не принимает. Таймаут опроса больше (180с из-за 20 шагов)
- Ключ HF передаётся только в заголовке `Authorization`; актуальную схему эндпоинтов смотреть в `GET /gradio_api/info`
- У бесплатного ZeroGPU два суточных лимита на токен: секунды GPU и **прогоны** (`runs`, 8/сутки). `getZeroGPUQuota()` сохраняет оба (`hf_current`/`hf_resets_at` и `hf_runs_remaining`/`hf_runs_limit`/`hf_runs_resets_at`), админка показывает две полосы — «Секунды» и «Прогоны»
- `getAvailableKey('huggingface')` пропускает ключи без доступных секунд (`< 60`) или прогонов (`0`); после сброса (`resets_at` в прошлом) устаревшие счётчики не блокируют ключ, а сам ключ считается свободным целиком (`hf_base` секунд, `hf_runs_limit` прогонов). Ротация выбирает следующий ключ **до** вызова, а не после отказа
- Выбор ключа с учётом идущих запусков (`rankHfKeys` в `src/lib/keys.ts`, атомарный выбор `claimHfKey` в `src/lib/hf-key-claim.ts`): запас ключа — меньшее из «прогонов осталось» и «секунд осталось ÷ `HF_RUN_SECONDS_ESTIMATE` (30 с на запуск)», из него вычитаются запуски, которые уже идут на этом ключе; берётся ключ с наибольшим запасом, при равенстве — с большим остатком секунд, ключи без замеров последними. Параллельные запуски поэтому разъезжаются по ключам, но один ключ с запасом может взять несколько подряд; занятый ключ не отклоняется — если заняты все, берётся лучший. Идущие запуски считаются по `generations.api_key_id` (`status = 'running'`, моложе `GENERATION_STALE_MS`): ключ записывается в строку в момент выбора, в одной транзакции с выбором под `pg_advisory_xact_lock('hf-key-claim')`, поэтому два одновременных запуска не берут один остаток; если к этому моменту строка запуска уже закрыта (ленивое закрытие, кредиты возвращены), ключ не выдаётся (`GenerationClosedError`) и попытка не тратит прогон ZeroGPU; миграции нет. Оценка 30 с — замер dev 2026-10-18 (Krea 2 около 20 с на запуск, Ideogram 4 больше, отдельно не мерилось); определяющим ресурсом у бесплатного ключа обычно оказываются прогоны (8 в сутки против 300 с)
- Исчерпание ZeroGPU приходит как `event: error` при HTTP 200 (сообщение Space может ссылаться на секунды, хотя причина — прогоны). Такой ответ распознаётся как `KeyExhaustedError` по словам `ZeroGPU`/`quota`: квота ключа тут же обновляется с `last_error`, ключ не выключается — дальше его отфильтрует остаток по `runs`. Прочие `event: error` — обычная ошибка с текстом из payload

## Обогащение промпта (LLM, стиль «42»)

- Каждая генерация сначала проходит через `src/lib/enhance.ts`: пользовательский запрос превращается в плотный англоязычный промпт в стиле «42» и только потом уходит в выбранный движок (Krea 2 или Ideogram 4). Для пользователя это невидимо; контракт `POST /api/generate` — `202` и опрос, как у «Ультры» (см. выше про воркфлоу Krea 2 и Ideogram 4), поле `engine` выбирает движок
- LLM — два OpenAI-совместимых провайдера в реестре `src/lib/llm.ts` (`LLM_PROVIDERS`), вызов — generic `callLlm({ provider, … })`:
  - `poolside` — `POOLSIDE_BASE_URL` (по умолчанию `https://inference.poolside.ai/v1`), `POOLSIDE_MODEL` (по умолчанию `poolside/laguna-xs-2.1`), thinking выключен через `providerOptions.poolside.chat_template_kwargs.enable_thinking`
  - `inception` (Inception Labs) — `INCEPTION_BASE_URL` (по умолчанию `https://api.inceptionlabs.ai/v1`), `INCEPTION_MODEL` (по умолчанию `mercury-2.5`); `reasoning_effort: low` передаётся штатной опцией `providerOptions.inception.reasoningEffort`; rate-limit заголовков нет → `rl_*` = `NULL`; 401/402/403/429 = «ключ не работает» (402 у Inception — биллинг/квота)
- Ключи LLM живут в той же таблице `api_keys` с `provider = 'poolside'` (префикс `sky_`) или `provider = 'inception'` (формат ключа не фиксирован — достаточно непустой строки); у HF-ключей `provider = 'huggingface'`. Ротация: `getAvailableLlmKey()` берёт из единого пула обоих провайдеров по заголовку `x-ratelimit-remaining-requests` и по 429/401/402/403; ключи без замеров (`NULL`, как у Inception) сортируются последними. При исчерпании всех ключей промпт собирается шаблоном `src/lib/style42-fallback.ts` — генерация не падает
- Системный промпт стиля — `src/lib/prompts/style42.system.ts` (TS-модуль, а не `.md`: текстовый импорт Bun не понимает NFT-трассировщик Vercel). SHA-хеш содержимого пишется в `generations.style_version` — по нему сравниваются итерации
- Серверные инварианты из промпта продублированы в коде (`src/lib/prompts/style-hints.ts`): явный стиль пользователя («фотореализм», «аниме», «детский рисунок» и т.п.) вытесняет якорь медиума, финальная формула с медиумом гарантируется постобработкой, экшен-детали и названный герой (мопс, кот, опоссум…; политик → Босс) проверяются по мини-глоссарию (потеряли — повтор с `MISSING DETAILS`)
- Замысел важнее канона: обилие 42 и свиты без просьбы — норма, ошибка только в подмене замысла. Место и цвета/свет из запроса (`detectUserSetting`/`detectUserPalette`) убирают якоря `location`/`lighting` из сообщения (строка `USER-DEFINED`). Якоря идут в начале сообщения, запрос пользователя — последним с напоминанием открыть промпт его героем. Если подлежащее первого предложения — свита из канона, о которой не просили (`hijackedOpening`), — повтор. Ответ LLM с мелкими огрехами (потерянная деталь, свита в начале) возвращается как лучший кандидат, шаблонный fallback — только когда LLM не ответила вовсе
- Якорь медиума всегда реалистичный (фото, 3D, кадр из фильма, обложка рэп-альбома); стилизации — только по запросу пользователя
- Бриф в конце сообщения (`buildBrief`): маленькая LLM теряет правила из длинного системного промпта, поэтому главное для конкретного запроса повторяется последними строками — `MAKE THE IDEA OBVIOUS` (действие и предметы запроса крупно и дважды), `GROUP` (3–5 участников группы описаны по отдельности, двух одинаковых образов нет), `LISTENING` (наушники на каждом, обложка альбома) и `42 VIBE` (выжимка приёмов из `docs/42_images/`: герой сам носит 42-образ, радужные лоскутные шубы, RGB, фантазийная свита, 42 на предметах, радужно-золотая палитра)
- Раздел «Гардероб, пестрота и 42-вайб» системного промпта описывает приёмы эталонов: замысел читается с первого взгляда, герой крупно; каталог образов; подсветка и эффекты; как 42 живёт на предметах; фантазийная свита; музыка. Флаги культа — горизонтальный двухцвет (синий верх, красный низ, белая 42 в золотом лавровом венке): «blue-and-red flag» генератор рисует как государственный
- Названный герой-животное (мопс, кот, свинья…) обязан быть в первом предложении, а действия «слушают» и «ест» проверяются по наушникам и еде (`missingDetails`); название альбома или трека («альбом Magnum») — точный текст на обложке (`extractNamedTexts`)
- Лексикон сообщества в системном промпте: Пятёрка/5opka, Magnum/Opus, взвод/рота/батальон (номер отряда, а не количество), братухи, SLAY, агитация — чтобы маленькая LLM не превращала «3 взвод» в трёх волков
- Политика текста: слова и лозунги появляются в кадре только по запросу. Текстовый запрос — кавычки «», “”, "" (`extractQuotedTexts`), слова «надпись/плакат/агитация/афиша/обложка» (`requestsText`) и лозунги капсом (`extractCapsPhrases`, строка `TEXT CANDIDATES`); «под названием X» (`extractNamedTexts`) — точный текст X. Без текстового запроса слоган-якорь не передаётся, а найденные в ответе цитаты маскируются постобработкой (`maskUnrequestedTexts`); точный текст пользователя переносится дословно и проверяется (`EXACT TEXT`). Кириллические имена из запроса, оставленные LLM без кавычек, берутся в кавычки (`quoteUserCyrillic`), а перед генератором «…» заменяются на "…" (`toGeneratorQuotes`) — ёлочки Krea рисует буквально. В блоке «Примеры» промпта цитируется только текст из INPUT примеров — это покрыто тестом-стражем
- Плотность и экшен: палитра по умолчанию — `hyper-saturated rainbow-and-gold`, промпт 200–300 слов (контракт обрезает на 2000 символах); промпт требует три слоя кадра, минимумы по существам/технике/роскоши/архитектуре (восьмой якорь `props` — абсурдный реквизит), ≥3 сюрприза и явное действие в первом предложении с усилением в 2–3 местах; реализм материалов и света обязателен, `toy-like`/`flat` запрещены
- В `generations` пишутся `enhanced_prompt`, `llm_key_id`, `llm_model`, `llm_tokens`, `enhance_ms`, `style_version`
- Жизненный цикл записи генерации (`src/lib/generations.ts`): строка появляется в статусе `running` ещё до списания кредитов; `POST /api/generate` принимает опциональный `id` от клиента (иначе страница не нашла бы процесс после обновления). Идущих запусков у пользователя не больше `MAX_RUNNING_GENERATIONS` (4, `src/lib/generation-limits.ts`): подсчёт и вставка строки идут в `startGeneration` одной транзакцией под `pg_advisory_xact_lock` по пользователю; на потолке 429 текстом лимита запросов (`TOO_MANY_REQUESTS_ERROR`), у «Ультры» то же. `cost` строки — списанные кредиты: списание (`chargeGeneration`) идёт одной транзакцией с отметкой на строке, а сбойное закрытие (`failGeneration`) и ленивое закрытие зависших — одной транзакцией с возвратом кредитов. Закрытие идёт по условию `status = 'running'`, поэтому возврат происходит ровно один раз — ни двойного, ни потерянного
- Неуспешные генерации тоже пишутся в `generations`: `status = 'failed'`, `cost = 0` (кредиты возвращены), исходный `prompt`, всё, что успело прийти от LLM, и причина в `error_message` в формате `<код>: <текст ошибки>` (`insufficient_credits`, `all_keys_exhausted`, `key_exhausted (<status>)`, `queue_timeout`, `error`, коды сбоев «Ультры», `interrupted`) — `src/lib/generation-error.ts`. Сбой этой записи логируется и не меняет ответ пользователю. Галерея `/api/generations` и `/api/admin/stats` считают только `status = 'completed'`. FK `api_key_id` — `ON DELETE SET NULL`, удаление HF-ключа не блокируется историей
- Обновление страницы не теряет процесс: `GET /api/generations/:id` отдаёт статус записи (с пресайннутой картинкой для завершённой), `GET /api/generations/active` — идущую генерацию пользователя (для вкладок без своего id), `GET /api/generations/running` — все идущие запуски пользователя (до потолка); клиент опрашивает идущие запуски одним циклом каждые 2,5 с. Зависшие `running` старше `GENERATION_STALE_MS` (16 минут: воркфлоу «Ультра» идёт до ~13–14 минут при агенте на 500 с, остальные движки укладываются в maxDuration; срок должен быть больше худшего прогона, это проверяет `ultra-budgets.test.ts`) лениво помечаются `interrupted` с возвратом кредитов
- Итерации стиля: `bun run eval:style42` (eval-файл `evals/style42.eval.ts`, датасет `style42-prompts`, метрики и скореры — в эксперименте Braintrust), визуальный прогон — `bun scripts/eval-images.ts [подстроки…]` (картинки в `docs/evals/images/`, вне git)
- Админка: блок «Ключи LLM» — селект провайдера (Poolside / Inception), добавление (`sky_` для Poolside, непустая строка для Inception), колонка «Провайдер», остаток запросов, токены, кнопка «Проверить и включить» (тестовый вызов) и удаление

## Режим «Ультра» (в коде идентификатор движка — `ultra`)

- Третий движок `ultra`, 10 кредитов. Запуск идёт воркфлоу Vercel Workflow (`workflows/ultra/`): `POST /api/generate` создаёт строку `running`, списывает кредиты, стартует воркфлоу через `start()` и сразу отвечает `202 { id, engine, cost }`; страница ждёт результат опросом `/api/generations/:id` (таймаут клиента 15 минут). Агент (`WorkflowAgent` из `@ai-sdk/workflow`, модель `gpt-6-luna` через подписку ChatGPT, рассуждение выбирает пользователь ползунком, по умолчанию `high`) сам выбирает входные изображения из библиотеки и принимает итог вызовом `generateImage` (инструмент только проверяет аргументы); картинку рисует отдельный шаг `draw` прямым запросом к приватному Codex Images (`/backend-api/codex/images/edits`, до 10 входных, формат и качество запрашиваются 1:1 и medium, но решает сервер). Пользователь видит только запрос и итог. Старый id `turbo` и сохранённое значение режима принимаются как алиасы для уже открытых вкладок; старый id также оставлен в ограничении БД для совместимости с предыдущим инстансом при выкладке. Новые ответы, записи и настройки используют `ultra`
- Код: `workflows/ultra/index.ts` (воркфлоу: `prepare`, цикл агента, `draw`, `complete`, при ошибке `fail` возвращает кредиты) и `workflows/ultra/steps.ts` (шаги, тонкие обёртки). В `src/lib/ultra/`: `library.ts` (библиотека как файловая система только для чтения), `ops.ts` (чтение для агента с превью WebP до 1024 px через `Bun.Image`, проверка аргументов, рисование), `tool-defs.ts` (описания инструментов), `agent-definition.ts` (`createUltraAgent`, общий для воркфлоу и `evals/ultra.eval.ts`; остановка по `acceptedImage`, `tooManyRejections` и `ULTRA_MAX_STEPS`), `codex-agent-model.ts` (модель с протоколом сериализации Workflow: в журнал уходит только `modelId`, токены читаются из базы внутри шага), `workflow-runtime.ts` (окружение шагов; тесты подменяют через `setUltraRuntime`), `failure.ts` (коды сбоев данными: код едет в начале текста ошибки, свойства ошибки не переживают границу шага), `start.ts` и `start-deps.ts` (приём запуска), `codex-auth.ts` и `codex-images.ts`. Инструкция агента — `src/lib/prompts/ultra.system.ts` (`buildUltraSystem(tree)`), общие блоки канона с обогащением лежат в `src/lib/prompts/canon.ts`; хеш инструкции (без дерева) пишется в `generations.style_version`
- Отбор входных изображений: только то, что запрос называет прямо или подразумевает. Обобщённые слова про людей («богема», «свита», «стримеры», «фанаты», «подписчики») — это запрос о конкретных людях из `личности`: агент читает описания (в них сказано, кто к какой компании относится) и прикладывает 2–4 портрета, а не рисует безымянную массовку. Человек, названный в запросе в любом падеже, включая через его фанатов или подписчиков («фанаты кай ангела»), появляется в кадре портретом из `личности`, а фанаты — безымянная толпа вокруг него в промпте; папка `личности` открывается, когда в кадре есть хоть один человек кроме Пятёрки (прогон-промах 2026-10-10: «фанаты кай ангела…» прочитались как массовка, портрет не приложился, ни одного чтения `личности/описания.txt` за прогон не было). Образ Пятёрки выводится из выпавшей идеи, а не глазным вкусом: агент формулирует, что идея требует от героя (действие, настроение, формат кадра), отбирает два-три кандидата из разных родов, открывает их (`readFile`) одним раундом и каждой фразой решает «тянет идею — не тянет»; решение остаётся за аргументом, взгляд корректирует. Запретов на открытие изображений в инструкции нет: readFile открыт для кандидатов снимка Пятёрки, близких вариантов и перепроверки выбранного (владелец: правило просмотров снимков не деградировало при правке аргумента). Кстати, мир вокруг — по «Матрице и мобам»: Пятёрка — игрок с админскими правами (артефакты-читы: перчатка, крюк, сандалиты-кирпичи, шапка с ушками), безымянная ботва — мобы и NPC, подписчики — живые 3500 против помпезности, так Шрэк разматывал утончённых. «Костюм со Слэя» — не дефолт для громкой сцены, а один из нарядных. Снимки трёх родов: нарядные (слэевский, свадебный, причёска в цветах флага — вид вшит и остаётся опорой), нейтральные базы (портрет стримера, наушники, тёмные очки, чёрно-белый defo — своего костюма нет, герой одевается промптом с нуля, вещи с особой полнотой, чтобы будничность базы не волочилась в кадр; «burger king» — нейтральный по одежде, но крепкий к месту) и нарочито простой `simple knee-up`: его смысл — показать Пятёрку простым, на расслабоне, в полной самоудовлетворённости (слон на водопое, свинья в грязи, ему всё по кайфу); никого не разматывает, борьбы нет, и он только под абсолютный быт или чистый расслабон, не дефолт дворовых сцен. Диагностический набор 2026-10-10: по одному запросу на каждый снимок Пятёрки — 9/9 попаданий после двух тегов-правок (defo — не «печать/арт», а живое дурашливое движение в полный рост: танец, пантомиму; причёска-флаг — весь эффект в самой причёске, байт одним видом без действий и нарядов, иначе агент уходит в слэевский). Второй дефолт-подмена (2026-10-10, после первой правки): три прогона подряд взяли наушники — «нейтральная база оденется с нуля» оправдывает любой снимок, поэтому в правило добавлены сравнение не меньше двух родов и запрет аргумента «удобно одевать». Названный образ берётся по имени файла. Слэевский костюм давил выбор частотой упоминаний в инструкции, поэтому примеры и якоря разнесены по свадебному, наушникам и уличным снимкам (владелец: образы в примерах фигурируют с одинаковой частотой). Описания не пересказывают, как выглядит снимок: вид узнаётся из самого изображения. Картинок «от себя» — свиты, реквизита, сюрпризов — в `images` нет: они живут текстом промпта. Тест-страж на кавычки: точный текст уходит генератору с прямыми кавычками (`toGeneratorQuotes` в `drawImage`, `src/lib/ultra/ops.ts`)
- Творческое направление: инструкция «Ультра» (`src/lib/prompts/ultra.system.ts`) написана связной прозой, без пронумерованных правил и выкриков ALWAYS/NEVER, по образцу инструкций крупных сервисов: роль → что такое 42 → как придумывать кадр → рабочий цикл → верность запросу → библиотека → промпт для генератора → инструменты → особые запросы → примеры → самопроверка → дерево библиотеки. Дерево стоит в самом конце: всё до него одинаково для всех запросов, поэтому провайдер кэширует эту часть, а хеш версии (`generations.style_version`) считается по инструкции с пустым деревом. Агенту нужно **понимание направления, а не набор атрибутов**: раздел «Что такое 42» рассказывает, что это за сообщество (вокруг Пятёрки/Босса, взводы и батальоны, пресейвы Magnum/Opus, премия SLAY) и как выглядит визуальный язык картинок сообщества (сверка по 25 кадрам `docs/42_images/` и подборки `at42`, разбор в `docs/superpowers/specs/2026-10-10-turbo-reference-gap.md`): праздник вокруг пустяка, раздутый до эпоса; сюжет, место, жанр и цвет у каждой картинки свои, общий язык: **знакомое место, безумие в нём** (двор, класс, деревня, казарма, площадь, сцена; выдуманный мир только когда он и есть шутка), **герой-владыка** на наряженной ездовой махине, **братуха-лоск** на каждом своём, включая зверей (меховая шуба, золотая цепь с кулоном 42, тёмные очки, кепка с банданой, джерси, кроссовки; в версии под образ, а не одним набором), **42 крупно и по-спортивному** (число как номер на джерси высотой с торс на груди, решётке трактора, шарах, ящиках, камне; мелкий медальон не считается), **хайп в лицах и телах** (рты открыты, кулаки, палец в камеру), **блеск и зрелище** (золотая и хромированная техника, лазеры из глаз, фейерверки, конфетти), **размножение** (один образ до горизонта и роем в небе, различия в цвете меха и мелочи), **упаковка в жанр и реальные вещи** (Fairy, JBL, «Роллтон», Adidas; фирменная надпись на вещи часть вещи) и **свои шутки племени** (солнце и деревья с лазерами, корова в пиксельных очках). Язык обязателен, меняется его версия; сюжетные вещи словаря (мопс, самокат, диско-шар, золото) если сваливать вместе в каждый кадр это штамп. Идею агент придумывает сам: пять-восемь кардинально разных идей (свой приём, герой, место и жанр у каждой), выбирает между ними `random`, одна фраза «кто, что делает, где, в чём шутка», приёмы поиска шутки (буквально, ритуал, техника с характером, роли наоборот, масштаб, торжество не там); подробный запрос уже содержит идею, её не заменяют, а доводят. Квот и каталогов обязательных существ нет; у каждой детали должен быть ответ «что она делает для шутки», у каждой находки облик из материала, действие и место. **Штамп** назван набором, а не запретом: мопсы в шубах, диско-шар, самокат или квадроцикл, золотой трактор, горы золота, трон и корона, фейерверк, петух и бегемот вместе допустимы, только если их просит запрос или в них сама шутка; штамп бывает и в сюжете («пустяк вызвал всеобщую спасательную операцию»). Узнаваемость проверяется вопросом «если закрыть числа, флаги и надписи, это всё ещё 42: событие огромное, настроение хайп, свои в пёстрой одежде, цвет и свет громкие?». «Верность запросу» «Ультра» пишет сам: общий блок `CANON_FIDELITY` остался только у обогащения Krea/Ideogram. Случайных якорей в сообщении агента нет (`buildUserMessage(input, null, …)`), а строка про запрос без текста своя (`NO_TEXT_LINE` в `src/lib/ultra/agent.ts`): число 42 только там, где ему есть естественное место, один-два раза, иначе агент расставлял его по плану в каждом кадре. Главный критерий качества прогона (владелец): агент не действует по шаблону и каждый раз аргументированно создаёт разные идеи и разные основы Пятёрки; организационно это идёт через `random` для идей и решений, вывод образа Пятёрки из выпавшей идеи с одной фразой-аргументом и разнесённые по образам примеры. Проверка направления: `bun run eval:ultra` на разных запросах (без рисования это почти не тратит лимит подписки) и подсчёт штампов и видов зверей в итоговых промптах; примеры инструкции не должны совпадать с запросами набора проверки, иначе агент копирует свой пример. Результаты итераций: `docs/superpowers/specs/2026-10-07-turbo-creative-direction-design.md`
- Критерии готового кадра в инструкции «Ультра» (`# Критерии готового кадра`, `src/lib/prompts/ultra.system.ts`) написаны от слабых мест, найденных прогонами и сравнением с эталонами, а не от числа людей (толпа нормисов получается сама, и она не безумие): **несочетаемость** (у каждой фигуры своё дело, не связанное с главным событием и соседями; ожидаемые пары вроде «крот-строитель» не считаются; проверка по одной фигуре), **эпатаж** (нарушены несколько правил сразу: масштаб, физика, роль, место; серьёзность растёт вместе с абсурдом; предметы из «не того» материала, у которого есть причина в замысле), **насыщенность** (три плана с отдельным сюжетом, у света есть источник и воздух, который его показывает, палитра выводится из мира идеи и не берётся из привычного закатного неба, нет тусклых зон и пустых мест, каждая вещь фирменная, один герой позирует в камеру), **проработка** (облик, действие, место у каждой находки; причина и след события; группы разобраны по одному), **реакция зрителя** (первая секунда, пересмотр, вопрос «что там происходит?»). У агента нет памяти между запросами: ссылок на «прошлые картинки» в инструкции нет (тест-страж), разнообразие между запросами (и между прогонами одного запроса) даёт **инструмент `random`** (`src/lib/ultra/random.ts`, `pickRandom`): список вариантов на вход, один случайный элемент на выход, меньше двух вариантов — `ok: false`. Раздел инструкции `## Решает случай`: сначала агент придумывает пять-восемь кардинально разных идей и разыгрывает их одним вызовом (если идея дана в запросе, разыгрываются способы её довести), затем под выпавшую идею сам придумывает десять-двадцать решений кадра (место, время суток, цвет, жанр, основа наряда, махина, вселенные мешапа, вторая группа, ракурс…) и разыгрывает каждое своим вызовом в одном раунде; выпавшее не переигрывается, названное пользователем не разыгрывается. Причина: выбирая сам, агент на один вход давал одну и ту же идею («смысл жизни» дважды подряд стал древесным великаном) и одни и те же решения (корона 6 из 6, бархат 5 из 6). Варианты одного решения различаются **видом, а не оттенком**: прогон «виндовс 42 против линукс» дал пять мест «снежный перевал, замёрзшая станция, ледниковый овраг, снежная взлётка, ледяной мост» и четыре палитры, и все со льдом, то есть кубик выбирал между сортами одного (доля холодных слов в вариантах 45–79%). Причина в теме (Linux пингвин, пингвин лёд; Windows синий; сервер стекло и хром) и в нашей инструкции: идея включала место и жанр (выпавшая «снежная» идея красила весь кадр), а правило чистого кадра называло лёд. Поэтому: идея это приём, герой, действие и шутка, а место, время суток, цвет и носитель разыгрываются отдельно; в каждом списке один-два варианта против тяги темы; холод назначается идеей, а не тягой темы. Инструмент без `"use step"`: `Math.random()` в воркфлоу зависит от зерна прогона (документация `workflow`, `foundations/workflows-and-steps.mdx`), поэтому у прогонов разный выбор, а воспроизведение прогона даёт тот же; в тестах источник подменяется (`createUltraAgent({ random })`). Выпавшее видно в `run.randomPicks` и в output эксперимента `evals/ultra.eval.ts`, в базу не пишется. Большой словарь знаков `# Словарь 42` (одежда, техника, миры, существа, зрелище, вещи) остаётся источником слов для вариантов. Столкновение разных миров в одном кадре как обязательный критерий не вводилось: решение владельца. Надписи в кадре: с 2026-10-10 по решению владельца слова в запросе писать не нужно («Пятёрка и Дерзко дают концерт, пока Генсуха завидует»), реплики и плакаты придумывает агент сам, когда их требует сцена: до трёх коротких фраз по одной-четыре слова, в голосе говорящего (недруг ворчит, свои ликуют) и на своём носителе (облачко, баннер, вывеска); когда слова сцене не нужны, в кадре ни одной буквы; точный текст пользователя в кавычках по-прежнему дословно (это касается только «Ультра», обогащение Krea/Ideogram работает по прежней политике). `NO_TEXT_LINE` в `src/lib/ultra/agent.ts` теперь «TEXT: not specified…»; кириллица в плакатах у генератора иногда плывёт (буква в слове), поэтому фразы короткие
- Образ героя в инструкции «Ультра» описан карточкой персонажа, а не словом («кот», «рыбак» без карточки пустое место): кто он на самом деле и в чём его необычный концепт, повадка и вайб, во что одет сверху вниз и почему именно так, что в руках и как делает, где на нём знак сообщества. **Одежда на языке племени в версии под образ** (меха, цепи, очки, джерси, кроссовки, пайетки), у героя запроса из статуса владыки, а не из профессии или бытового дела (при «обычном будничном дне» агент одел героя в фартук и тапки; героя наряжает статус, дело остаётся бытовым), и не из общей «коробки смешных материалов»: пока в примерах инструкции повторялись дуршлаги, самовары, прихватки, губки, пена и закатное розово-фиолетовое небо, у всех кадров была одна одежда и один цвет (замер на шести запросах: розовый, фиолетовый, оранжевый и бирюзовый в 6 из 6 промптов, губки в 6 из 6, дуршлаг в 5 из 6). Когда подсказку «одежда из мира идеи» усилили, ушли в латунь, бархат и броню (11 из 11 промптов), без мехов, очков и крупных номеров: язык племени нельзя вытеснять «исторической» одеждой. Поэтому инструкция не содержит ни списков материалов и палитр, ни квот (число слоёв, предметов, цветов), а примеры не делят общих материалов и цветов и показывают очки, крупный номер и золотую цепь в трёх-четырёх из семи (тест-страж `ultra-prompt.test.ts`; цепь на каждом герое и из предметов темы стала шаблоном, см. пункт «Золото и белый в «Ультре»» ниже). **Уличный тест**: одна цветная вещь («фиолетовая форма», «красная лента», «синий пиджак») одеждой не считается, и слова «обычный», «простой» в карточке героя не нужны даже при просьбе об обычном (повод бытовой, а выглядит герой так, что его не пропустить). **Ничего по умолчанию**: всё названное, но не описанное, генератор достраивает самым средним вариантом (замок из серого камня, серый асфальт, голубое небо), поэтому у каждого существительного кадра есть материал, цвет, состояние и странность, фон описан как герой. **Каждая вещь фирменная**: знак сообщества (число 42, корона, лавровый венок, цепь с кулоном, нашивка взвода) стоит на технике, одежде, предметах, а не только на герое, число пишется крупно и по одному на предмет (мелкие цифры генератор путает); строка про запрос без текста `NO_TEXT_LINE` в `src/lib/ultra/agent.ts` не ограничивает число знаков. Ездовая махина и главная вещь сюжета наряжены не беднее хозяина. Публика жанра (красная дорожка, парад) одета в безумный стиль жанра, обычные люди одним-двумя со странным делом. **Как собирается безумие** (отдельный раздел инструкции, по разбору `docs/42_images/Фантастический парад черепашьего босса.png`): наращивание (основа и четыре-шесть надстроек разных категорий с экипажем: черепаха → бронированная → огнедышащая → в очках → с шипами → с пушками → пушками управляют мопсы → мопсы в костюмах), рекурсия (надстройки раскрываются на третий уровень), превосходная степень внутри вещи («скипетр из всех драгоценностей мира»), сломанная логика (бриллианты стреляют лазерами из глаз), массовка из комбо (существо + транспорт + лоск + 42) и подчинение всего идее; агент сначала строит в уме дерево наращивания, потом пишет промпт по веткам. Прогон «Пятёрка и Дерзко дают концерт, пока Генсуха завидует» (аниме-постер, жирафы на самокатах с 42, Генсуха в окне диспетчерской среди серых сумок) выявил ещё пять поправок, внесённых в инструкцию: (1) костюм с входного изображения агент пересказывал («чёрно-белый костюм Слэя… накидка с одной стороны, крыло с другой»): он остаётся как на картинке, пишутся только изменения и дополнения; (2) придуманная реплика вышла по-английски («Must be nice!»): слова пишутся на языке запроса; (3) в концерте не было публики: зал есть в кадре у концерта, премии, парада, матча, выступления и митинга, даже если запрос о нём молчит; (4) Генсуха вышла мелкой в окне далёкой башни: «другой уровень» значит отдельно от сцены, а не далеко и мелко, недруг занимает не меньше шестой части кадра (врезка, экран, край переднего плана); (5) фигуры мелкие при уйме свободного места: герои и названные предметы вместе занимают не меньше двух третей кадра, свободное место значит «приблизь камеру». Слова распределяются по смыслу (герои, публика, названные предметы и недруг не меньше, чем площадка и свет, а при нехватке сокращается площадка; восьмисот слов хватает), оговорка точности «exactly as in Image N» пишется один раз на всех людей. - Библиотека: бакет, префикс `library/`, ключи `library/<папка>/<файл>`; в каждой папке изображения и текстовый файл `описания.txt` — свободные описания словами владельца, без формата (по ним агент выбирает файлы). Описания пишет человек, а не ИИ-агент: агент их не сочиняет и не переписывает, а только заливает то, что написал владелец, и переносит строки при переименовании файла. В описании нет очевидного (видно из имени файла или папки, уже сказано строкой выше) и общеизвестного (то, что агент и так знает, например кто такой Дуров), только то, чего по файлу и общим знаниям не узнать; любые другие `.txt` в папке (например, тексты, которые владелец положил рядом с обложками) заливаются как есть, агент читает их через `readFile`. Источник — папка `library/` в корне репозитория (вне git, как `docs/evals/images/`), за пределы репозитория скрипт не смотрит; заливка `bun scripts/sync-library.ts` (dev) и `NODE_ENV=production bun scripts/sync-library.ts --yes-prod` (prod). Разрешения владельца заливка библиотеки не требует: это часть выката, после любой правки `library/` (файлы, описания, перенос между папками) заливать и в dev, и в прод; `--yes-prod` только страхует от случайного запуска. Порядок для прода: `--dry-run`, сверка продового `описания.txt` с локальным (чтобы не затереть правки, сделанные только в проде), заливка, повторный `--dry-run` («загружено 0»). Скрипт ничего не удаляет: после переноса файла в другую папку старый ключ убрать через `deleteImage` из `src/lib/storage.ts`. Дерево папок для инструкции строится на каждый запрос (кэш в памяти до минуты): у папки число изображений и текстов («2 изображения, 10 текстов»), `описания.txt` текстом не считается, пустая папка помечена «пусто». Страница в режиме «Ультра» показывает ползунок (shadcn `Slider`, подписи «Среднее / Высокое / Очень высокое / Максимальное», выбор в `localStorage` `gen42-reasoning`), `POST /api/generate` принимает необязательное `reasoning` (нет поля — `high`, неизвестное значение — 400 «Некорректный уровень рассуждения»), `startUltra` сохраняет уровень в `generations.reasoning` и кладёт его во вход воркфлоу, `createUltraAgent({ reasoning })` передаёт его модели. Для старых записей значение остаётся `NULL`; миграция добавляет CHECK `NOT VALID`, а `src/lib/migrate.ts` валидирует его отдельным SQL-запросом, чтобы не удерживать сильную DDL-блокировку на скане всей таблицы. Цена не зависит от уровня (10 кредитов); прогоны, запущенные до выбора, идут на `high`. Замеры на запросе про концерт (один прогон на уровень, лимит подписки после каждого сдвинулся меньше процента): `high` агент 111 с, 136 тыс. токенов; `xhigh` 266 с, 201 тыс.; `max` 335 с, 210 тыс., в промпте 891, 951 и 990 слов (правило «до 950 при публике» `max` нарушил); `medium` не мерился. Модель `gpt-6.1-sol` на этих настройках за 180 с не успела (агент до рисования не дошёл, расход окна 5 часов 2%, недели 1%): на `luna` остаёмся. Сравнение уровней и моделей: `ULTRA_EVAL_MODEL`, `ULTRA_EVAL_REASONING`, `ULTRA_EVAL_AGENT_TIMEOUT_MS` для `evals/ultra.eval.ts`
- Бюджеты времени: агент до 500 с (`ULTRA_AGENT_TIMEOUT_MS`; это не лимит платформы, а наш абсолютный срок на все вызовы модели: каждый вызов идёт отдельным шагом с лимитом функции 300 с, а общего потолка на прогон у Workflow нет, документация `worlds/vercel.mdx` и сравнительные таблицы), рисование до 270 с (`ULTRA_DRAW_TIMEOUT_MS`, запрос к Codex обрывается сам раньше лимита функции); рисование без повторов (`drawStep.maxRetries = 0`): у Codex Images нет ключа идемпотентности. Шаги идут внутри уже запущенного вызова `flow`, а лимит функции считается от старта вызова, поэтому у функций Workflow задан `WORKFLOW_V2_TIMEOUT_MS=10000` (`scripts/build-vercel.ts`): после любого шага длиннее 10 с продолжение уходит в очередь и следующий шаг стартует в свежем вызове (по умолчанию для 300 с это 2 минуты, и рисование, стартовавшее на 80-й секунде вызова, платформа убила бы раньше его таймера). Сбой шага ведёт к шагу `fail` (возврат кредитов, ровно один раз), мёртвый вход Codex помечается для админки; сбои самого рантайма Workflow (`REPLAY_TIMEOUT`, `MAX_DELIVERIES_EXCEEDED`, `DEPLOYMENT_MISMATCH`, ошибка загрузки бандла) шаг `fail` обходят, и строку тогда закрывает ленивое закрытие через 16 минут. Порядок «худший прогон (агент 500 с + рисование 270 с + очередь, ~14 минут) < ожидание страницы (`ULTRA_CLIENT_WAIT_MS`, 15 минут) < закрытие зависших (`GENERATION_STALE_MS`, 16 минут)» держит `ultra-budgets.test.ts`; накладные расходы очереди и реплея в «~14 минут» это оценка, не замер (`evals/ultra.eval.ts` идёт в одном процессе без Workflow). **Принятое ограничение, не проверено на Vercel**: у отдельного вызова модели нет своего таймера, абсолютный срок 500 с больше лимита функции 300 с на шаг, поэтому одиночный вызов дольше ~290 с платформа оборвёт, а чистого `agent_timeout` не будет (кредиты вернёт ленивое закрытие через 16 минут). Средний вызов на `max` около 12 с (27 вызовов за 335 с), так что случай редкий. Усиление, если он проявится: обернуть `options.abortSignal` в `CodexAgentModel.doGenerate`/`doStream` через `AbortSignal.any([…, AbortSignal.timeout(280_000)])`; сначала проверить по документации Workflow, как повторяется шаг с обычной ошибкой (по умолчанию шаги повторяются), иначе повтор вызова на 280 с выведет прогон за срок закрытия зависших. Ревью PR #23 (2026-10-10) других находок уровня выше minor не дало

- **Вложения пользователя** (issue #36): в режиме «Ультра» скрепка у поля прикладывает до 5 своих файлов по 10 МБ (PNG/JPEG/WebP/TXT/MD). Файлы грузятся прямо в S3 по presigned PUT (`POST /api/attachments/sign` → PUT → `POST /api/attachments/complete`), потому что тело функции Vercel ограничено 4,5 МБ; CORS бакета проверяет `scripts/storage-cors.ts` (на dev и prod правило уже стоит; `PutBucketCors` через S3 API Neon beta отвечает `NoSuchBucket`, менять правило — в Neon Console). Сервер проверяет фактический объект в S3 (формат картинки, UTF-8 текста) и удаляет битый файл. Папка `attachments/<userId>/<scope>/` живёт только до конца запуска: её удаляют `completeStep`/`failStep`, сироты старше 24 часов убирает суточный крон. Агент видит её как папку `вложения` первой в дереве; текст больше 120 000 символов читается началом с пометкой. Scope хранится в `generations.attachment_scope` и передаётся воркфлоу отдельно от id записи.

## Деплой на Vercel

- Сборка для Vercel собственная, в формате Build Output API (`vercel.json`: `framework: null`, `buildCommand: bun run build:vercel`). Пресет `framework: bun` не годится: его сборщик сам компилирует серверный код и не применяет плагин Workflow, из-за чего `start()` не получает идентификатор воркфлоу («invalid workflow function»). `scripts/build-vercel.ts` собирает сервер `Bun.build` одним файлом (`functions/index.func/server.js`, рядом `dist/`, без `node_modules`); функции Workflow (`flow.func` с триггером очереди и `webhook`) создаёт `workflow build --target vercel-build-output-api`; у всех функций `runtime: bun1.4.x`, `architecture: x86_64`, а рядом с каждой лежит `bunfig.toml` с `[install] auto = "disable"`: файловая система функции только для чтения, и Bun 1.4 при импорте несуществующего модуля запускает автоустановку пакетов, пытается записать `node_modules/.cache` и убивает процесс ошибкой «bun is unable to write files: EROFS» на первом запросе (воспроизводится локально на read-only диске: `bwrap --ro-bind / / …`); с отключённой автоустановкой это обычное исключение `ERR_MODULE_NOT_FOUND` с именем модуля. Крон из `vercel.json` Vercel добавляет в `config.json` сам (вручную туда не писать: дублируется). Каталог вывода с точки в начале (`.output`) сборщик Vercel не принимает, а `workflow build` принимает за исходники всё в папках проекта вне своего списка игнорируемых (`.vercel` в нём есть), поэтому бандл сервера пишется прямо в `.vercel/output`
- `maxDuration: 300` функции сайта записан в `scripts/build-vercel.ts` (Hobby+Fluid допускает до 300с). С выходом Krea и Ideogram на воркфлоу функция сайта сама их не ждёт: она создаёт строку, списывает кредиты, стартует воркфлоу и отвечает `202`; опрос Space (до 180с у Ideogram 4) идёт шагом `generate` в вызове `flow` с лимитом 300с, поэтому одна попытка укладывается в лимит шага. У `flow` `maxDuration: "max"`
- «Ультра» не упирается в лимит одного вызова: агент и рисование это отдельные шаги воркфлоу, и благодаря `WORKFLOW_V2_TIMEOUT_MS` каждый длинный шаг стартует в своём вызове `flow` с лимитом 300 с (Hobby). В проекте Vercel должны быть включены системные переменные окружения («Automatically expose System Environment Variables»): без `VERCEL_DEPLOYMENT_ID` `start()` выберет Local World и попытается писать `.workflow-data` на read-only диск, и каждый запрос «Ультра» закончится ошибкой с возвратом кредитов. Замеры на dev (прогоном с рисованием, до перехода на Workflow): запросы без героев 70–90 с, с четырьмя входными героями 90–420 с (рисование делает от 1 до 12 внутренних проходов по 25–35 с, число плавает у провайдера независимо от промпта; ручек качества, размера, формата, модели и `service_tier` у Codex Images нет; рассуждение агента `high` стоит 20–50 с до первого токена), см. `docs/superpowers/specs/2026-10-07-turbo-creative-direction-design.md`. Размещение обработчика очереди и результаты проверок: `docs/superpowers/specs/2026-10-08-turbo-workflow-design.md`
- Зависимости сервера сайта целиком в бандле `Bun.build`, поэтому `includeFiles` и ошибки `Cannot find package 'X'` из-за разных условий exports (старая сборка пресета) больше неактуальны. Не попадает в бандл только то, что подключено строкой, вычисляемой в рантайме (в `src/server.ts` это dev-маршрут `flow`, в продакшене он выключен)
- Локальная проверка сборки: `npx --yes vercel@latest build` (установленный CLI может быть старее схемы триггера `queue/v2beta`; в `vercel.json` триггер очереди писать без поля `consumer`, имя потребителя строит Vercel), затем из `.vercel/output/functions/index.func` запустить `PORT=3056 NODE_ENV=production bun --env-file=<путь к .env.development> server.js` и проверить `/` и `/api/models`
- **Авто-деплой**: проект подключён к GitHub (`42-Z/gen42`, прод-ветка `main`) — пуш в `main` собирает прод, другие ветки дают preview. Hobby-план не подключает приватные репо организаций, поэтому репозиторий публичный; при возврате приватности авто-деплой переносить на GitHub Actions (`vercel deploy --prod` по токену)
- Ручной выкат: `vercel deploy --prod --yes`. **Изменения env вступают в силу только после нового деплоя**
- **Необходимые переменные окружения обязательно добавлять на Vercel** (production и preview) через `vercel env add` и редеплоить: прод их не видит, пока не будет нового деплоя. Локально новые переменные класть в `.env.development`, шаблоны — в `.env.example`
- Env переменные: не перетирать прод-специфичные значения локальными (например `BETTER_AUTH_URL` = прод-домен). Секреты Vercel помечены sensitive и не вытягиваются обратно (`vercel env pull` отдаёт `[SENSITIVE]`); добавлять/обновлять через `vercel env add NAME <environment> --force`, значение — из stdin. App-секреты дублируются в GitHub Actions secrets (`gh secret set -f <file>`)

## Процесс изменений (обязательно)

- **Работа начинается с Superpowers, а не с кода.** Любая задача — фича, баг, рефакторинг, документ, проверка — сначала проходит вход в набор: `using-superpowers` → `brainstorming` (классификация задачи, вопросы, одобрение дизайна) → `writing-plans` (план) → `executing-plans` или `test-driven-development` (реализация) → `verification-before-completion` (доказательства готовности). Код, написанный до классификации и одобрения дизайна, считается браком и откатывается, даже если он работает и проходит тесты; загрузить скилл после замечания владельца — тоже брак. Для мелкой задачи процесс короче, но не отменяется: классификация и короткий дизайн в чате до первой правки.
- **Документация направляет каждый этап работы**: проектирование, реализацию, отладку, проверку и наблюдение за поведением. Перед каждым шагом читать документацию версии, которая стоит в проекте (для AI SDK — скилл `ai-sdk` и `node_modules/ai/docs`; для остального — официальные доки и скиллы), и делать так, как она описывает, а не минимально рабочим костылём из памяти. Нужна возможность, которой нет в коде, — сначала искать штатный механизм (например, колбэки жизненного цикла и `result.steps` агента вместо самодельных обёрток), и только если его нет — решать иначе и говорить об этом явно
- **На каждую задачу — соответствующий скилл, даже если работа кажется мелкой.** Скиллы лежат в `.agents/skills/` (shadcn — UI, `vercel-cli` — deployments/env Vercel, `agent-browser` — браузер и живые проверки, `braintrust` — evals, старшие процессные — `superpowers`/`writing-plans`/`verification-before-completion` и т.д.): перед шагом загрузить подходящий и следовать его инструкции; если скилла нет — работать по документации (пункт выше), а не изобретать метод. Обещание «успею и без скилла» — способ пропустить проверенные практики
- **Плюсы и минусы вариантов — только по фактам.** Каждое утверждение о варианте опирается на источник: страницу документации версии проекта или результат проверки на деле. Отсутствие примера или упоминания в документации — не минус и не риск, а статус «не проверено»: он записывается отдельно и закрывается проверкой, а не снижает оценку варианта. Минус — измеримая цена: что сломается, сколько работы, денег, времени или лимита. Разовая правка кода, конфигурации или переменных окружения минусом не считается. Варианты сравниваются по полной цене, включая код, который придётся писать и поддерживать самим (самодельный механизм не «проще», чем штатный механизм платформы). Осторожность без данных не причина отвергать вариант или рекомендовать другой: нет данных — сначала проверка, потом рекомендация. Вывод о варианте формулируется как «подтверждено», «не проверено» или «опровергнуто» с источником
- **Коммиты — по ходу работы, без отдельной просьбы владельца.** Законченные логические единицы (скилл, спека, фича с тестами) коммитятся на рабочей ветке, не в `main`; сообщение по-русски, в духе истории репозитория. Артефакты прогонов (`docs/evals/*.jsonl`, `captures/`) в коммит не попадают без просьбы. **Готовую ветку всегда пушить и открывать PR — это стандартный шаг, выбора нет; и не бросать PR на полпути: следить за его CI, доводить проверки до зелёных и до мержа, красный CI чинить в этой же ветке**; мерж в `main` и разрушительные действия на проде — только с явного разрешения владельца, всё остальное по правилу в пункте ниже
- **Не пушить и не предлагать мерж незавершённое.** Владелец сам решает, когда работа закончена, и может ещё захотеть что-то добавить или переиначить: недоделанные изменения в remote и преждевременное «давайте мержить» этому мешают. Финальный пуш, открытие PR и merge — только после его явного «готово»; зелёный CI и отсутствие ревью-замечаний сами по себе готовностью не считаются. До этого держать работу локальной, коммитя по ходу логические единицы (см. пункт выше); статус работы неясен — спросить «считаешь ли готовым?», а не докладывать о готовности
- **Новая ветка — сразу переменные Preview, иначе превью PR падает.** Переменные Preview привязаны к ветке, у только что запушенной они пустые: сборка проходит («Ready»), а сайт на превью отвечает `FUNCTION_INVOCATION_FAILED`, в `vercel logs` — `BetterAuthError … BETTER_AUTH_SECRET`. Дудл монтируется только на время показа, поэтому в покое в DOM нет ни рисунков, ни анимаций, ни слоёв. Рисовка — по иллюстрациям зверей Duolingo из их блога (собаки, кошка, лягушки; смотреть глазами, а не по описаниям; мопса сверяли с их собаками рядом в одном масштабе, первая версия с круглой головой, глянцевыми глазами, линией рта и дугой цепи не совпала ни в чём): голова и тело — блоки с малым скруглением одного цвета шерсти, без контура и без линии рта; глаза — белый круг с тёмным круглым зрачком без блика (у зверей Duolingo блик только у самого Дуо), при желании с плоским «сонным» веком цвета шерсти (`EyeDot`, параметры `lid` и `lidH`); нос — тёмная «таблетка»; язык — полукруг с плоским верхом из-под морды; уши — плоские лоскуты или скруглённые треугольники темнее шерсти; ноги и тень под персонажем — «таблетки»; второй тон того же цвета внутри тела (`t-l` светлое брюшко, `t-d` пятна и окорок); мало фигур (у Duolingo «14 — хорошо, 30 — слишком много», у нашего мопса 17 элементов из-за короны и «сонных» век). Не совпадает сознательно или из-за палитры: цвета фиолетово-розовые, а не естественные; морда мопса темнее шерсти (признак породы), у Duolingo морда светлее; глаза крупнее, чем у их зверей. Цвета — только опоры листа (`--d-0…--d-5`, `--d-w`, `--d-l`, `--d-n` из `src/lib/sheet/css.ts`), золота и жёлтого нет; тёмные детали сливаются с тёмным фоном шапки, поэтому ушам и рогам берутся светлее. Видимого текста в дудлах нет (цифры 42 — рисунок). Покачивание головой и моргание — приёмы idle-анимации Duolingo (по их блогу о Rive); «сплющивание и растяжение» при появлении — решение автора, в их материалах не подтверждено. Чтобы добавить персонажа: компонент в `doodles/`, вид в `DOODLES` и `ART`, движение `dk-<вид>` в `doodles.css` (у человека — отдельный `src/doodle-<вид>.css` с `@import` в `src/index.css`), имя в сценарий `ui:check`; кадры смотреть рендером в Playwright с паузой анимаций на нужных моментах, а не вслепую.
- Палитра листа: фон одного семейства оттенков (индиго → фиолетовый, относительная яркость L ≤ 0,018 — активная кнопка всегда заметна), «хребет» (всё, что несёт белый текст: кнопки, активная вкладка) 0,178 ≤ L ≤ 0,1833, «спектр» (заливки без текста: слайдер, полосы квот, рамка ожидания и её фазовый слой) до `#ff5ca8`; маски фазового слоя мягкие и крупные, без чётких краёв; цвета нигде не задаются вручную, золота и жёлтого нет. Шрифты: display (заголовки, логотип, крупные числа, класс `font-display`) — **Gogh ExtraBold** (Type Forward; `src/fonts/gogh-extrabold.woff2` — подмножество оригинала: латиница, кириллица, `№`, знаки препинания, 18 КБ; подключён `@font-face` в `src/index.css`, Bun вшивает его в CSS; геометрический гротеск с круглыми формами и плотным штрихом; одно начертание; диапазон весов `100 900` и `font-synthesis: none`, чтобы не рисовался искусственный жирный; у `font-display` `letter-spacing: 0.01em`, `tracking-tight` на display-элементах не ставить; в файле есть OpenType-функция `tnum`, так что `tabular-nums` работает), основной текст — Inter Tight (Google Fonts). Шрифт выбран по красоте среди тех, где в файле есть полная кириллица (Inter, Manrope, Cruinn, Gogh; в файлах Neutral Sans кириллицы нет, у Anallop её нет в списке глифов); лицензию владелец вынес за рамки выбора. Справка: в файле `OS/2 fsType = 4` (встраивание для просмотра и печати), соглашение — на typeforward.com, у Type Forward есть платная веб-лицензия по просмотрам страниц, бесплатными помечены только ExtraBold и ExtraBold Italic, а условий бесплатной версии на их странице нет. Длинный текст и мелкий UI этим шрифтом не набирать: одно начертание. Прежний display-шрифт Gothic №60 владелец отклонил («криво», «не подходит для градиентных историй»), а Bricolage Grotesque в Google Fonts не содержит кириллицу (подмножества latin, latin-ext, vietnamese), поэтому русские заголовки с ним рисовались запасным Inter Tight. Анимируются только `transform`, `translate`, `scale`, `rotate`, `opacity` (2D `translate`, не `translate3d`); запрещены `filter`, `backdrop-filter`, `mix-blend-mode`, тени, `@property`; постоянного `requestAnimationFrame` нет, без событий идёт одна анимация (дрейф фона, 90 с); непрерывные анимации (дрейф, течение потока, движение фазового слоя ожидания) только ступенчатые (`steps()`): плавные заставляли композитор рисовать кадр 60 раз в секунду (замер трассировкой: 2,6 с отрисовки за 3 с в покое против 40 мс со ступенями); при `prefers-reduced-motion: reduce` всё движение отключено.
